# UI 근거와 인터랙션 계약

v0.5.0 G1~G7 구현·자동 검증과 GTX 1060 직접 GPU·CPU 음성 인식은 **PASS**다. 실제 Windows UI, YouTube/reference 전체 흐름, 자동 GPU→CPU 제품 전환, 1~8시간 자원 비교는 **HOLD 또는 BLOCKED**이며, G7 병렬 선택 항목은 disabled/HOLD로 노출하지 않는다.

구현 담당: 버전 시작 승인 시 확정. 현재 문서 정본은 Codex/Sol이 관리한다.

## 사용자와 한 가지 핵심 작업

- 사용자: 긴 방송을 혼자 정리하는 버튜버 또는 클리퍼
- 핵심 작업: 분석을 맡기고 상태를 감독한 뒤, 근거가 있는 후보만 빠르게 채택/제외
- 정보 순서: 입력 → 실행 상태 → 현재 근거 → 후보 검토 → 다음 행동

## 시각 방향

방송 조정실의 **슬레이트와 탤리 라이트**를 모티프로 한다.

- 배경: 청회색 슬레이트
- 패널: 밝은 종이색
- 주요 행동: 보랏빛 스튜디오 컬러
- 실행 중: 청록 신호
- 주의/중단: 호박색 탤리
- 시간·점수: 고정폭 숫자
- 기본 글꼴: Windows `Segoe UI`, 시간 표시는 `Cascadia Mono`/`Consolas`

시그니처 요소는 후보마다 오디오·발화·채팅 신호를 세 줄로 보여 주는 **Signal Rail**이다. 장식용 차트가 아니라 왜 후보가 선택됐는지 설명한다. 채팅은 화면 오른쪽 영역의 움직임 변화량이며 OCR 결과가 아니다.

## 핵심 상태와 행동

| 상태 | 화면 | 가능한 행동 |
|---|---|---|
| 빈 상태 | 실제 로컬 파일, 공개 YouTube 단일 영상, 데모 시나리오 | 작업 만들기 |
| 준비 | 입력 요약, 처리 단계 | 시작 |
| 실행 중 | 정확한 단위 진행률, 현재 단계, 활동 이벤트 | 취소 |
| 취소 중 | 현재 종료 대상, 마지막 heartbeat, 경과 시간 | 기다리기 |
| 취소/중단 | 마지막 완료 단위와 이유 | 재개 |
| 실패 | 사용자 언어의 원인과 다음 행동, 진단 상세 접기 | 재개 또는 새 작업 |
| 검토 준비 | 후보 목록, 원본 구간 플레이어, Signal Rail, 근거, 작업 용량 | 재생·타임코드 복사·CSV·채택/제외/보류·작업 삭제 |

## 키보드

- `Ctrl+O`: 로컬 파일 선택
- `Ctrl+Enter`: 작업 시작
- `Esc`: 실행 중 안전한 취소 요청
- `R`: 중단된 작업 재개(입력 필드 포커스 밖)
- `A`: 선택 후보 채택
- `X`: 선택 후보 제외
- `J` / `K`: 다음/이전 후보

모든 단축키에는 동일한 버튼이 있고 포커스 링을 숨기지 않는다.

## 반응형

- 1280px 이상: 입력/상태 레일 + 작업 본문 + 활동 패널 3열
- 900~1279px: 활동 패널을 본문 아래로 이동
- 899px 이하: 1열, 후보 카드 내 Signal Rail 유지, 주요 버튼은 전체 폭

## 정직한 진행 표시

- 시간 기반 애니메이션으로 퍼센트를 추측하지 않는다.
- Rust Core가 청크 체크포인트까지 저장한 완료 단위만 반영한다.
- YouTube 다운로드 중에는 yt-dlp가 보고한 영상·오디오 스트림 진행률을 결합해 표시하고, 완료 뒤부터 분석 체크포인트를 표시한다.
- 음성 인식 청크 2개 전에는 남은 시간을 `계산 중`으로 표시하고, 이후 최근 2~4개 청크 처리 속도로 ETA를 계산한다.
- heartbeat가 오래되면 “진행 중” 대신 “응답을 기다리는 중”으로 바꾼다.

## v0.3.3 후보 검토 계약

### 정렬

- 기본은 종합 점수 높은 순이다.
- 원본 시간, 오디오 반응, 발화 밀도, 채팅 움직임, 판정 상태로 바꿀 수 있다.
- 정렬은 계산된 점수나 판정을 수정하지 않고 화면 순서만 바꾼다.
- 정렬을 바꿔도 현재 선택, 재생 위치, 채택·보류·제외 상태를 유지한다.
- 점수가 같은 후보는 원본 시간순으로 고정한다.

### 밝은 화면·어두운 화면

- 기본값은 Windows 시스템 설정을 따른다.
- 사용자는 시스템 설정 사용·밝게·어둡게 중 하나를 선택할 수 있다.
- 두 화면에서 정보 위계와 Signal Rail의 의미가 같아야 한다.
- 색상에만 의존해 성공·주의·실패·선택 상태를 구분하지 않는다.

### 전후 맥락과 바로가기

- 후보 선택 시 현재와 같이 원본 해당 시점으로 이동한다.
- 후보 앞뒤 음성 인식 문장과 타임코드를 함께 보여 준다.
- 후보 시작, 맥락 시작, 맥락 끝으로 이동하는 명시적 행동을 제공한다.
- 맥락 범위가 원본 시작·끝을 넘지 않으며, 같은 프록시를 반복 생성하지 않는다.
- 이야기 후보가 도입되면 이야기 전체와 내부 반응 후보를 서로 다른 단계로 표시한다.

### 업데이트 상태

- 기존 자동 확인과 설정의 업데이트 확인 버튼을 유지한다.
- 최신 상태, 새 버전, 확인 실패, 분석 종료 후 설치 대기를 구분한다.
- 업데이트 연결 실패를 분석 실패처럼 표시하지 않는다.

## v0.3.4 안정성·접근성 UI 계약

- 화면 오른쪽 위 설정 진입점은 톱니바퀴 아이콘, `설정` 문구와 버전을 함께 표시한다. 버전 문자열만 있는 아이콘 버튼으로 숨기지 않는다.
- 설정 버튼은 마우스 올림·키보드 포커스·눌림 상태가 보이며 세 화면 폭에서 다른 상태 표시와 겹치지 않는다.
- 입력 카드 배경은 테마 변수를 사용한다. 밝은 화면·어두운 화면에서 기본·마우스 올림·선택·비활성화·키보드 포커스 상태를 각각 구분한다.
- 비활성화되지 않은 입력 카드를 회색 처리해 사용할 수 없는 항목처럼 보이게 하지 않는다.
- 취소 중에는 `취소 중…`만 반복하지 않고 현재 종료 대상, 마지막 응답 시각과 경과 시간을 표시한다.
- 취소 제한 시간을 넘기거나 강제 종료가 필요하면 그 사실과 안전하게 재개할 수 있는 마지막 완료 지점을 설명한다.

## 후속 보류 UI 계약

YouTube 자막 검색 UI와 검색 결과의 원본 시각 이동, 이야기 후보와 외부 API 재정렬 화면은 v0.5.0에 구현하지 않는다. 별도 버전에서 다시 승인할 때 참고한다.

- 이야기 후보에는 시작·절정·마무리 근거와 전체 길이를 표시한다.
- 외부 API 재정렬은 사용자 동의·제공처·모델·비용 한도를 포함한 별도 계약으로 다룬다.

## v0.5.0 품질·작업 대기열 UI 계약

G1~G7 구현·자동 검증은 **PASS**이며, 실제 설치 창·사용자 흐름 확인은 **HOLD**다. 아래 순서를 화면의 정보와 행동 순서로 유지한다.

### 1. YouTube 자막 출처와 품질

- YouTube 입력에서는 일반 VOD의 `한국어 자동 자막`을 우선하고, 자동 자막이 없거나 사용할 수 없을 때만 `제작자 한국어 자막`을 사용한다. 자동 번역·다른 언어·`live_chat`은 선택하지 않는다.
- 자막 상태에는 원본 영상 시간 기준, 각 시작 시각이 끝 시각보다 앞서고 두 시각이 원본 영상 길이 범위 안에 있는지, 겹침·중복·긴 공백·일정한 시간 오프셋 검증 결과를 표시한다. 실제 기준 영상 전에는 시간 허용 오차나 시간 오차 합격 임계값을 표시하거나 확정하지 않는다.
- 두 자막이 없거나 자막·구간을 확인할 수 없으면 `로컬 Whisper로 확인 중`을 표시하고 해당 자막·구간을 대체 처리한다. 자막 검색 UI와 검색 결과의 원본 시각 이동은 이 버전에서 제공하지 않는다.
- 진단 상세에는 원본 자막 파일, 제작자·자동 출처, 언어, 트랙 식별자와 파일 SHA-256을 연결한다.

### 2. GPU·CPU Whisper 제어

- 시작 전에 실행 모드 `자동(GPU 우선)`·`GPU`·`CPU`, 속도·정확도 단계 `빠르게`·`균형`·`정확하게`, CPU 사용량·스레드 수 제어를 보여 준다.
- GPU는 시험 실행이 성공한 뒤에만 `GPU 사용 중`으로 표시한다. 시험 또는 실행 실패 시 해당 청크와 이유를 기록하고 CPU로 한 번 전환한다.
- 앱을 다시 열어도 GPU 실패·CPU 대체 상태를 복원한다. CPU도 실패하면 작업을 `실패`로 끝내며 같은 청크를 반복 실행하는 진행 표시를 만들지 않는다.

### 3. 음성 인식 품질 안전장치와 선택 후보 재음성 인식

- 기존 이상 음성 인식 안전 구현은 재사용 가능한 품질 안전장치로 유지한다. 반복·깨진 문자는 `음성 인식 결과 불확실`과 이유로 표시하고 불확실한 문장을 후보 제목에 사용하지 않는다.
- 사용자가 선택한 후보에만 `다시 음성 인식`을 제공한다. 자동 반복은 없으며, 결과 개정·실행 ID·실패 이유와 이전 판정을 함께 확인한다. 구현·자동 테스트는 `PASS`, 실제 흐름은 `HOLD`다.

### 4. 렉과 자원 상태

- 단계별 처리 시간·CPU·메모리·디스크·자식 프로세스를 표시하되 측정 전 임의 합격선을 만들지 않는다. 경고와 강제 중단은 서로 다른 상태와 문구로 표시한다.
- 분석 중 취소·화면 이동·현재 상태 확인이 가능해야 하며, 강제 중단 뒤 마지막 완료 지점과 실패 이유를 설명한다.

### 5. 후보 수와 내용 품질

- 후보 수는 `8개`·`20개`·`30개` 중 작업별로 선택하며 기본값은 `20개`다. 부족한 개수를 빈 카드나 낮은 품질 후보로 채우지 않는다.
- 후보 카드에는 `왜 선택됨`과 `무엇이 불확실함`을 표시하고, 깨진 문자·비정상 반복·근거 부족·중복의 효과와 게임·소리·조용한 대화 예외를 설명한다.
- Signal Rail은 `채팅 영역 움직임`으로 표시한다. 현재 VOD 고정 영역의 평소 분포보다 움직임이 늘어난 보조 신호일 뿐이며, 작성자·메시지 수·이모티콘 정보를 표시하지 않는다.

### 6. 순차 대기열

- 여러 영상을 등록하기 전에 파일명·입력 종류·대기 순서를 확인하고, 기본적으로 분석 작업 하나만 실행한다.
- 작업은 `대기`, 현재 단계, `중단됨`, `검토 준비`, `실패`, `취소` 상태와 진행률을 표시한다. 실패·취소는 이유와 `다시 시작`을 보여 주되 자동 재시작하지 않는다.
- 앱 강제 종료 뒤 `중단됨`으로 멈추고 사용자 재개·취소 전에는 다음 작업도 시작하지 않는다. 실행 중 삭제는 취소→자식 종료→종료 저장 뒤에만 제공하며 삭제 실패를 숨기지 않는다.

### 7. 제한적 병렬 처리

- 기본값은 `순차 처리`다. 실제 측정으로 안전성이 확인되기 전까지 병렬 선택 항목을 노출하지 않는다.
- 자원 부족으로 순차 처리로 전환되면 이유를 한 번 알리고 앱을 다시 열어도 자동으로 병렬화를 켜지 않는다. 안전성이나 총시간 이득이 부족하면 항목을 노출하지 않는다.
