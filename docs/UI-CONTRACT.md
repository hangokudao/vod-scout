# UI 근거와 인터랙션 계약

구현 담당: 버전 시작 승인 시 확정. 현재 문서 정본은 Codex/Sol이 관리한다.

## 사용자와 한 가지 핵심 작업

- 사용자: 긴 방송을 혼자 정리하는 버튜버 또는 클리퍼
- 핵심 작업: 분석을 맡기고 상태를 감독한 뒤, 근거가 있는 후보만 빠르게 채택/제외
- 정보 순서: 입력 → 실행 상태 → 현재 근거 → 후보 검토 → 다음 행동

## 확인한 레퍼런스

| [Codex app-server 이벤트 문서](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md) | 시작/완료 이벤트, 진행 델타, 명시적 종료 상태라는 원칙 | 프로토콜 또는 코드를 그대로 복제 |

## 시각 방향

방송 조정실의 **슬레이트와 탤리 라이트**를 모티프로 한다.

- 배경: 청회색 슬레이트
- 패널: 밝은 종이색
- 주요 행동: 보랏빛 스튜디오 컬러
- 실행 중: 청록 신호
- 주의/중단: 호박색 탤리
- 시간·점수: 고정폭 숫자
- 기본 글꼴: Windows `Segoe UI`, 시간 표시는 `Cascadia Mono`/`Consolas`

시그니처 요소는 후보마다 오디오·발화·채팅 신호를 세 줄로 보여 주는 **Signal Rail**이다. 장식용 차트가 아니라 왜 후보가 선택됐는지 설명한다. 채팅은 화면 오른쪽 영역의 움직임 변화량이며 OCR 결과가 아니다.

## 핵심 상태와 행동

| 상태 | 화면 | 가능한 행동 |
|---|---|---|
| 빈 상태 | 실제 로컬 파일, 공개 YouTube 단일 영상, 데모 시나리오 | 작업 만들기 |
| 준비 | 입력 요약, 처리 단계 | 시작 |
| 실행 중 | 정확한 단위 진행률, 현재 단계, 활동 이벤트 | 취소 |
| 취소 중 | 현재 종료 대상, 마지막 heartbeat, 경과 시간 | 기다리기 |
| 취소/중단 | 마지막 완료 단위와 이유 | 재개 |
| 실패 | 사용자 언어의 원인과 다음 행동, 진단 상세 접기 | 재개 또는 새 작업 |
| 검토 준비 | 후보 목록, 원본 구간 플레이어, Signal Rail, 근거, 작업 용량 | 재생·타임코드 복사·CSV·채택/제외/보류·작업 삭제 |

## 키보드

- `Ctrl+O`: 로컬 파일 선택
- `Ctrl+Enter`: 작업 시작
- `Esc`: 실행 중 안전한 취소 요청
- `R`: 중단된 작업 재개(입력 필드 포커스 밖)
- `A`: 선택 후보 채택
- `X`: 선택 후보 제외
- `J` / `K`: 다음/이전 후보

모든 단축키에는 동일한 버튼이 있고 포커스 링을 숨기지 않는다.

## 반응형

- 1280px 이상: 입력/상태 레일 + 작업 본문 + 활동 패널 3열
- 900~1279px: 활동 패널을 본문 아래로 이동
- 899px 이하: 1열, 후보 카드 내 Signal Rail 유지, 주요 버튼은 전체 폭

## 정직한 진행 표시

- 시간 기반 애니메이션으로 퍼센트를 추측하지 않는다.
- Rust Core가 청크 체크포인트까지 저장한 완료 단위만 반영한다.
- YouTube 다운로드 중에는 yt-dlp가 보고한 영상·오디오 스트림 진행률을 결합해 표시하고, 완료 뒤부터 분석 체크포인트를 표시한다.
- 음성 인식 청크 2개 전에는 남은 시간을 `계산 중`으로 표시하고, 이후 최근 2~4개 청크 처리 속도로 ETA를 계산한다.
- heartbeat가 오래되면 “진행 중” 대신 “응답을 기다리는 중”으로 바꾼다.

## v0.3.3 후보 검토 계약

### 정렬

- 기본은 종합 점수 높은 순이다.
- 원본 시간, 오디오 반응, 발화 밀도, 채팅 움직임, 판정 상태로 바꿀 수 있다.
- 정렬은 계산된 점수나 판정을 수정하지 않고 화면 순서만 바꾼다.
- 정렬을 바꿔도 현재 선택, 재생 위치, 채택·보류·제외 상태를 유지한다.
- 점수가 같은 후보는 원본 시간순으로 고정한다.

### 밝은 화면·어두운 화면

- 기본값은 Windows 시스템 설정을 따른다.
- 사용자는 시스템 설정 사용·밝게·어둡게 중 하나를 선택할 수 있다.
- 두 화면에서 정보 위계와 Signal Rail의 의미가 같아야 한다.
- 색상에만 의존해 성공·주의·실패·선택 상태를 구분하지 않는다.

### 전후 맥락과 바로가기

- 후보 선택 시 현재와 같이 원본 해당 시점으로 이동한다.
- 후보 앞뒤 음성 인식 문장과 타임코드를 함께 보여 준다.
- 후보 시작, 맥락 시작, 맥락 끝으로 이동하는 명시적 행동을 제공한다.
- 맥락 범위가 원본 시작·끝을 넘지 않으며, 같은 프록시를 반복 생성하지 않는다.
- 이야기 후보가 도입되면 이야기 전체와 내부 반응 후보를 서로 다른 단계로 표시한다.

### 업데이트 상태

- 기존 자동 확인과 설정의 업데이트 확인 버튼을 유지한다.
- 최신 상태, 새 버전, 확인 실패, 분석 종료 후 설치 대기를 구분한다.
- 업데이트 연결 실패를 분석 실패처럼 표시하지 않는다.

## v0.3.4 안정성·접근성 UI 계약

- 화면 오른쪽 위 설정 진입점은 톱니바퀴 아이콘, `설정` 문구와 버전을 함께 표시한다. 버전 문자열만 있는 아이콘 버튼으로 숨기지 않는다.
- 설정 버튼은 마우스 올림·키보드 포커스·눌림 상태가 보이며 세 화면 폭에서 다른 상태 표시와 겹치지 않는다.
- 입력 카드 배경은 테마 변수를 사용한다. 밝은 화면·어두운 화면에서 기본·마우스 올림·선택·비활성화·키보드 포커스 상태를 각각 구분한다.
- 비활성화되지 않은 입력 카드를 회색 처리해 사용할 수 없는 항목처럼 보이게 하지 않는다.
- 취소 중에는 `취소 중…`만 반복하지 않고 현재 종료 대상, 마지막 응답 시각과 경과 시간을 표시한다.
- 취소 제한 시간을 넘기거나 강제 종료가 필요하면 그 사실과 안전하게 재개할 수 있는 마지막 완료 지점을 설명한다.

## v0.4.0 장시간 분석 UI 계약

- 분석 시작 전에 선택한 성능 단계, 예상 시간·저장 공간과 `자동(GPU 우선)`·CPU 경로를 설명한다.
- `빠르게`, `균형`, `정확하게`는 내부 모델명이 아니라 사용자가 기대할 결과와 비용으로 설명한다.
- GPU는 실제 시험이 성공한 경우에만 사용 중으로 표시한다. 실패 후 CPU로 전환되면 작업을 실패로 숨기지 않고 어떤 청크부터 전환됐는지 기록한다.
- YouTube 자막은 `제작자 원문`, `자동 생성 원문`, `로컬 음성 인식` 출처와 품질 상태를 표시한다. 자동 번역·다른 언어·품질 미달 트랙은 선택되지 않은 이유를 진단 상세에서 확인할 수 있게 한다.
- 현재 작업 검색은 검색어가 나온 문장·원본 시각·출처를 보여 주고 선택하면 원본 영상의 해당 시각으로 이동한다.
- 검색 실패와 자막 확보 실패를 전체 분석 실패처럼 표시하지 않으며 로컬 대체 처리 상태를 설명한다.
- 이야기 후보에는 시작·절정·마무리 근거와 전체 길이를 표시한다.
- 이야기 후보 안의 15~90초 반응 후보로 바로 이동할 수 있다.
- API 재정렬은 기본으로 끄고, 사용자가 제공처·모델·API 키를 등록한 경우에만 선택할 수 있게 한다.
- 외부 전송 전에 후보 수·전송 내용·예상 토큰과 비용·작업당 비용 한도를 보여 주고 사용자가 실행을 확정하게 한다.
- API 키나 네트워크가 없거나 호출이 실패해도 빈 화면이나 오류로 끝내지 않고 규칙 기반 결과를 표시한다.
