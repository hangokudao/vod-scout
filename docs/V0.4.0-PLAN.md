# VOD Scout v0.4.0 장시간 최적화·이야기 구간 탐색 계획

상태: **요구사항 고정 · 기준선 측정 전 HOLD**
UI/UX·프론트엔드 담당: Orca-Claude

## 최우선 원칙

v0.4.0의 첫 번째 성공 기준은 기능 수가 아니라 **긴 영상을 끝까지 안정적으로 처리하는 효율**이다. 8시간 영상을 한 번에 메모리에 올리거나 전체 프레임·전체 전사에 무조건 무거운 모델을 적용하지 않는다.

다음 원칙을 모든 구현보다 먼저 적용한다.

- 전체 영상은 저비용 신호로 빠짐없이 훑는다.
- 정밀 음성 인식·글자 인식·선택형 외부 AI는 가능성이 높은 구간에만 사용한다.
- 메모리·임시 파일·동시 실행 수에 상한을 둔다.
- 각 단계의 결과를 저장하고 중단 후 마지막 완료 지점부터 재개한다.
- GPU가 없거나 실패해도 CPU 경로로 완료할 수 있어야 한다.
- 측정 전 임의 수치를 성능 합격선으로 만들지 않는다.

## 핵심 사용자 요구사항

2시간 영상 안에 약 10분 동안 시작·전개·절정·마무리가 이어지는 사건이 있다면, 완벽한 편집점이 아니더라도 사용자가 검토할 만한 시작점과 끝점을 하나 이상의 이야기 후보로 제안해야 한다.

이 요구사항은 단순히 반응이 큰 45초 구간을 찾는 것과 다르다. 서로 이어지는 장면과 대화가 같은 사건인지 판단하고, 그 안에서 쇼츠·하이라이트로 다시 자를 수 있는 핵심 순간도 함께 보여 줘야 한다.

## 단계별 처리 구조

### O0. 기준선 측정

현재 v0.3.2 CPU 경로로 같은 영상의 처리 시간, 피크 메모리, 임시 파일 최대 크기, 최종 작업 용량, 전사량, 후보 품질을 기록한다. 이후 최적화는 같은 입력과 같은 측정 방법으로 비교한다.

### O1. 시작 전 자원 확인

- CPU 명령 집합, 논리 코어 수, 사용 가능한 메모리 확인
- 지원 가능한 GPU와 실행 경로 확인
- 원본 길이와 선택한 분석 방식으로 예상 작업 시간·저장 공간 안내
- 공간 부족 또는 지원하지 않는 GPU는 분석 시작 전에 설명
- 사용자가 `빠르게`, `균형`, `정확하게` 중 하나를 선택할 수 있게 하되 실제 모델·스레드 값은 측정 후 고정

### O2. 전체 영상 저비용 색인

전체 영상을 일정한 작은 구간으로 순차 처리해 다음 신호만 저장한다.

- 음량과 음량 변화
- 발화 유무와 침묵 길이
- 장면 전환과 화면 변화
- 채팅 영역이 지정된 경우 움직임 변화
- 기존 전사·체크포인트가 있으면 재사용 가능한 구간

원본 프레임과 전체 PCM은 저장하지 않는다. 축약된 시간축 신호와 경계 정보만 남긴다.

### O3. 적응형 전사

- 반응이 큰 구간, 사건 경계, 아직 확인하지 않은 시간대에 전사 예산을 우선 배정한다.
- 긴 영상 전체를 한 모델로 반복 전사하지 않는다.
- GPU가 있으면 넓은 범위를 빠르게 훑고, CPU에서는 예산 안에서 시간대가 한쪽으로 몰리지 않게 분산한다.
- 상위 후보 주변은 더 정확한 설정으로 다시 전사할 수 있다.
- 설정·모델·실행 경로가 바뀌면 호환되지 않는 체크포인트를 명확히 무효화한다.

### O4. 이야기 구간 연결

시간순 세그먼트를 노드로 보고 다음 관계를 연결한다.

- 같은 주제·인물·게임 상황으로 이어지는 대화
- 짧은 침묵 뒤 계속되는 같은 사건
- 장면 변화와 동시에 시작되는 새 사건
- 질문·도전·문제 제기처럼 시작 역할을 하는 표현
- 반응 상승·채팅 증가·발화 속도 증가처럼 전개와 절정을 나타내는 변화
- 요약·성공·실패·장면 전환처럼 마무리를 나타내는 변화

연속성과 반응 변화가 함께 높은 구간을 이야기 후보로 만들고, 각 후보에는 시작 근거·절정 근거·마무리 근거와 원본 타임코드를 저장한다. 규칙 기반 경로만으로도 동작해야 하며 외부 AI는 필수 조건이 아니다.

### O5. 상위 후보 정밀 분석

- 상위 이야기 후보와 주변 맥락만 정밀 전사한다.
- 채팅 글자 인식이 도입되면 움직임이 활발한 후보 주변 프레임에만 적용한다.
- 이야기 후보 안에서 기존 15~90초 반응 후보도 함께 표시한다.
- 같은 사건을 조금씩 겹쳐 여러 번 제안하지 않도록 이야기 단위 중복을 제거한다.

### O6. 선택형 사용자 API 재정렬

규칙 기반 결과가 준비된 뒤 사용자가 직접 등록한 API로 상위 후보만 재정렬할 수 있게 한다. 기본값은 꺼짐이며 API가 없어도 핵심 분석과 검토가 모두 완료돼야 한다.

- 초기 연결 대상은 DeepSeek를 포함한 OpenAI 호환 API로 한정하고, 다른 규격은 별도 호환성 시험 뒤 추가한다.
- 개발자 공용 API 키를 소스·설치 파일에 넣지 않는다. 사용자가 등록한 키는 Windows 보안 저장소에 보관하고 설정 파일·작업 폴더·체크포인트·로그·내보내기에 기록하지 않는다.
- 전송 전에 제공처·모델·후보 수·전송 내용·예상 토큰과 비용·작업당 비용 한도를 표시하고 사용자의 실행 동의를 받는다.
- 원본 영상·음성·전체 8시간 음성 인식 결과는 보내지 않는다. 규칙으로 추린 상위 후보의 음성 인식 결과와 신호 요약만 전달한다.
- 응답은 기존 후보 식별자의 순서·요약·근거만 반환하게 제한한다. API가 새 타임코드나 존재하지 않는 후보를 만들 수 없게 한다.
- 연결 실패, 잘못된 키, 응답 형식 오류, 비용 한도 초과 시 규칙 기반 결과를 그대로 제공한다.
- 실제 전송량과 사용 토큰을 작업 기록에 남기되 API 키와 인증 헤더는 남기지 않는다.

## GPU 전사

### 필요한 동작

1. 앱 시작 또는 분석 시작 전에 실제 실행 가능한 GPU 경로를 시험한다.
2. 시험 전사와 메모리 할당이 성공한 경우에만 GPU를 선택한다.
3. 실행 중 메모리 부족·드라이버 오류·비정상 종료가 발생하면 해당 청크를 CPU로 다시 처리한다.
4. 결과에는 사용한 장치, 모델, 스레드 수, 처리 시간을 기록한다.
5. CPU 결과와 타임코드·체크포인트 형식이 호환돼야 한다.

GPU용 실행 파일과 DLL은 CPU 경로와 분리된 선택형 묶음으로 검토한다. 지원 장치와 실행 방식은 실제 Windows 하드웨어 시험이 끝난 뒤 확정하며, 확인하지 않은 GPU를 지원한다고 표시하지 않는다.

## Whisper 성능 단계

사용자에게 내부 옵션을 그대로 노출하지 않고 세 단계만 제공한다.

| 사용자 선택 | 목표 | 기본 동작 |
|---|---|---|
| 빠르게 | 전체 흐름과 후보 위치 우선 | 저비용 색인과 제한된 적응형 전사 |
| 균형 | 후보 내용과 속도의 균형 | 넓은 색인 후 상위 후보 재전사 |
| 정확하게 | 선택 범위의 전사 품질 우선 | 사용자가 지정한 범위 또는 상위 후보를 더 정확하게 재분석 |

모델 크기, 스레드 수, GPU 사용, 전사 예산의 실제 조합은 O0 기준선과 하드웨어 시험 뒤 문서에 고정한다.

## 8시간 영상 최적화 단계

### 1단계: 구조 검증

- 96분·10청크 구조 시험
- 메모리 상한, 한 청크 임시 파일, 체크포인트 무효화 단위 테스트
- 전체 시간축 색인이 입력 길이에 비례해 선형으로 증가하는지 확인

### 2단계: 1~2시간 실제 영상

- 서로 다른 방송 화면과 말하기 밀도를 가진 영상 사용
- CPU와 가능한 GPU 경로 비교
- 취소·재개, 앱 강제 종료 후 재개, 저장 공간 부족 오류 확인
- 사람이 표시한 이야기 구간과 제안 결과의 겹침·시작 오차·끝 오차 기록

### 3단계: 8시간 빠른 분석

- 실제 8시간 영상 또는 사용자가 승인한 동등한 입력을 처음부터 끝까지 처리
- 처리 시간, 피크 메모리, GPU 메모리, 임시 파일 최대 크기, 최종 작업 용량 기록
- 중간 취소·재개와 앱 재실행을 각각 한 번 이상 확인
- 남은 자식 프로세스와 삭제되지 않은 임시 PCM·프레임이 없는지 확인

### 4단계: 8시간 정확 분석

빠른 분석이 PASS한 뒤에만 진행한다. 자원 비용과 사용자 가치가 확인되지 않으면 기본 기능이나 기본 홍보 문구에 포함하지 않는다.

## 추가로 필요한 지원 기능

- 하드웨어·성능 진단 보고서 내보내기
- 분석 전 예상 시간·저장 공간 안내
- CPU/GPU 실행 경로와 모델 묶음 관리
- 필요할 때 받은 모델의 확인·삭제 기능
- 분석 설정과 데이터 출처를 후보에 남기는 근거 정보
- 동일 입력·동일 설정 결과를 재사용하는 지문 기반 캐시
- 이야기 후보를 사람이 수정하고 채택 근거를 남기는 평가 화면
- 기준 영상과 사람이 표시한 구간을 관리하는 품질 평가 자료

## 완료 조건

1. 현재 CPU 경로와 새 경로를 같은 입력으로 비교한 기준선이 있다.
2. GPU가 있으면 시험 후 사용하고 실패하면 같은 청크를 CPU로 완료한다.
3. 메모리와 임시 파일 사용량이 영상 전체 길이만큼 한꺼번에 증가하지 않는다.
4. 2시간 기준 영상의 사람이 표시한 이야기 구간에 겹치는 후보가 하나 이상 제안된다.
5. 이야기 후보의 시작·절정·마무리 근거와 타임코드를 검토할 수 있다.
6. 8시간 빠른 분석의 시간·메모리·저장 공간·취소·재개 결과가 기록된다.
7. API 키와 네트워크 연결이 없어도 규칙 기반 분석이 완료된다.
8. 선택형 API는 상위 후보의 축약 정보만 보내며 실행 전 예상 토큰·비용 한도를 표시하고 실패 시 규칙 결과를 보존한다.
9. 기존 v0.3.2 작업 데이터는 보존되며 호환되지 않는 중간 결과만 명시적으로 다시 계산한다.

성능 측정 전에는 “8시간 완전 지원”, “GPU 지원”, “이야기 구간 정확 탐지”라고 표시하지 않는다.
