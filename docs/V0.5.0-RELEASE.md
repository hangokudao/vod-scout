# VOD Scout v0.5.0 릴리스 작업 정본

상태: **구현 전 HOLD**

계획 정본: [v0.5.0 품질·작업 대기열 개선 계획](V0.5.0-PLAN.md)

현재 공개 버전은 v0.4.0이다. 이 문서는 v0.5.0 구현·검증 결과를 기록할 자리이며, 아직 제품 버전 변경·패키징·배포를 승인하거나 완료로 표시하지 않는다.

## 목표

시청자 약 5~30명 규모의 치지직 버츄얼 스트리머 방송에서 음성 인식 오류와 후보 품질을 개선하고, 여러 영상을 안전하게 순서대로 처리한다. 핵심 분석은 외부 AI와 유료 API 없이 완료돼야 한다.

## 포함 범위

1. 반복 문구·깨진 문자 등 불확실한 음성 인식 결과 표시와 후보 제목 보호
2. 분석 단계별 렉·CPU·메모리·디스크·자식 프로세스 측정과 자원 제한
3. 후보 8·20·30개 설정과 기본값 20개
4. 후보 내용 품질 경고와 선택 이유 표시
5. 여러 영상의 기본 순차 대기열, 순서 변경, 개별 취소, 수동 재시작
6. 실제 시험을 통과한 GPU 우선 실행과 실패 청크의 CPU 자동 전환
7. 측정 결과가 안전할 때만 제공하는 제한적 병렬 처리

## 비범위

- YouTube 자막 검색과 검색 결과의 원본 시각 이동
- 수분 단위 이야기 후보와 멀리 떨어진 관련 장면 연결
- 채팅 글자 인식·작성자 식별·채팅 영역 자동 탐색
- 사용자 API·외부 AI 후보 재정렬
- 완성 쇼츠 렌더링·자동 게시
- Authenticode 인증서 구매·적용

비범위 항목은 구현 중 필요해 보여도 추가하지 않고 후속 목록에 기록한다.

## 확정된 사용자 환경

- 주요 입력은 치지직 저스트채팅·게임 VOD다.
- 채팅은 익명 화면 오버레이이므로 작성자 ID와 고유 참여자 수를 사용하지 않는다.
- 채팅은 현재 VOD의 고정 채팅 영역 움직임이 내부 평소 분포보다 증가했는지를 보조 신호로만 사용하며 실제 메시지·참여자 증가로 표현하지 않는다.
- 현재 움직임 분석으로 일반 문장과 이모티콘을 구분했다고 주장하지 않는다.
- 채팅이 없거나 적어도 오디오·말하기·화면 근거로 작업이 완료돼야 한다.

## 종료가 보장되는 처리 규칙

- 실패·취소 작업은 자동 재시작하지 않는다. 사용자가 요청할 때만 재시작한다.
- 같은 청크의 GPU 실패 뒤 CPU 자동 전환은 한 번만 수행한다.
- GPU 실패와 CPU 대체 처리 상태를 청크별로 저장한다. GPU 실패가 기록된 청크는 앱 재실행 뒤 GPU로 돌아가지 않으며, CPU 처리도 실패하면 해당 작업을 `FAILED`로 끝내고 다음 대기 작업을 시작한다.
- 품질 경고만으로 후보를 자동 재분석하지 않는다. 사용자 행동 한 번당 실행 ID 하나만 만들며 완료·실패가 다른 재분석을 자동 호출하지 않는다.
- 병렬 처리의 자원 조건을 충족하지 못하면 순차 처리로 한 번 전환해 상태를 저장하고, 앱 재실행 뒤에도 다시 자동으로 병렬화하지 않는다.
- 앱 재실행 시 실행 중이던 작업은 `INTERRUPTED`로 멈추며 사용자 재개·취소 전에는 자동 재개하거나 다음 작업을 시작하지 않는다.
- 강제 자원 상한 초과 시 현재 작업 소유 자식만 종료하고 체크포인트와 이유를 보존한 뒤 `FAILED`로 끝내며 설정을 바꿔 자동 재시작하지 않는다.

## 호환성과 데이터 보존

- v0.4.0 작업을 열기만 해서는 기존 후보를 다시 계산하거나 덮어쓰지 않는다.
- 체크포인트 구조가 바뀌면 스키마 버전과 호환 판정을 먼저 추가한다.
- 후보 수 변경·수동 재분석 결과는 새 후보 개정으로 저장한다. 동일한 안정적 후보 ID에만 판정을 이어받고 ID가 달라진 후보는 미판정으로 시작한다.
- 이전 후보 개정, 사용자 판정, 원본 타임코드와 스키마 변경 전 v0.4.0 정상본을 보존한다.
- 대기열의 각 영상은 독립된 작업 ID와 작업 폴더를 사용한다.
- 시작 전 대기 작업과 종료 상태 작업만 즉시 삭제한다. 실행 중 삭제는 취소, 해당 작업 자식 프로세스 0개 확인, 종료 상태 저장 뒤 정규화한 `jobs/{job-id}` 하위 폴더를 삭제하고, 성공한 뒤에만 대기열 참조를 제거한다.
- 개별·전체 삭제가 실패하면 참조와 `삭제 실패` 상태를 유지하며 다른 작업이나 대기열 순서를 변경하지 않는다.

## 보안과 외부 전송

- 새 외부 AI·유료 API·API 키 저장 경로를 추가하지 않는다.
- 원본 영상·음성·음성 인식 결과는 외부로 보내지 않는다.
- GPU 실행 파일·DLL·모델을 추가할 경우 출처·버전·SHA-256·라이선스를 고정하고 설치 경로에서 다시 검증한다.
- 로그에는 인증 정보, 개인 절대 경로, 원시 외부 도구 전체 출력을 남기지 않는다.

## 필수 검증

기본 자동 검증:

```powershell
npm.cmd test
npm.cmd run build
cargo test --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/fixture-worker/Cargo.toml
```

추가로 [테스트와 완료 기준](TEST-PLAN.md)의 v0.5.0 항목을 실행한다. 실제 영상·GPU·설치본 검증을 실행하지 못하면 결과를 `HOLD`로 남긴다.

## PR 형식 리뷰 게이트

- 입력 검증과 작업 ID·삭제 경계
- v0.4.0 체크포인트·사용자 판정 호환성
- 취소와 앱 종료 뒤 자식 프로세스 정리
- 단일 앱 실행권과 `INTERRUPTED` 작업의 수동 복구
- 대기열 실패가 다음 작업을 막지 않는지
- 자동 재시작·GPU 재시도·병렬 전환이 반복되지 않는지
- 외부 바이너리 출처·SHA-256·라이선스
- 개인정보·외부 전송·API 키 경로가 새로 생기지 않았는지
- 장시간 메모리·임시 파일·동시 프로세스 상한

미확인 항목은 `PASS`로 바꾸지 않는다.

## 알려진 한계와 HOLD

- 기준 영상의 사용 권한·보관 범위와 실제 입력은 아직 확정하지 않았다.
- 실제 GPU 지원 범위는 시험 전까지 확정하지 않는다.
- Authenticode 부재와 SmartScreen 경고는 v0.5.0 비범위다.
- YouTube 봇 확인은 로그인 자동화나 CAPTCHA 우회로 해결하지 않는다.
- v0.4.0 exact HEAD의 순간 최대 임시 파일 재측정은 별도 검증 HOLD다.

## 롤백

- 기능 PR 병합 전 회귀가 확인되면 변경을 `main`에 반영하지 않고 공개 v0.4.0 정본을 유지한다. 작업 브랜치 삭제는 별도 승인 없이는 수행하지 않는다.
- 병합 후 회귀가 확인되면 v0.5.0 태그·자산을 덮어쓰지 않고 수정 버전을 준비한다.
- 롤백 과정에서도 기존 작업 폴더와 설치 폴더를 자동 삭제하지 않는다. 스키마 변경 전 보존한 v0.4.0 정상본과 이전 후보 개정을 유지해 공개 v0.4.0에서 읽던 원본 작업을 복구할 수 있게 한다.
