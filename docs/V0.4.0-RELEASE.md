# VOD Scout v0.4.0 릴리스 기록

상태: **HOLD — 기능 P0·버전 정렬·로컬 NSIS 본문 PASS, updater 서명·installer smoke·공개 배포는 태그 Actions 전**

## 목표와 비범위

v0.4.0은 긴 YouTube 영상을 로컬 CPU 경로로 안정적으로 내려받고 분석하는 P0를 공개한다.

포함 범위:

- 청크 단위 장시간 처리와 제한된 후보 수
- 체크포인트 schema 4 호환성·손상 복구·재개
- 범위 밖 및 음량·대화 근거가 없는 후보 제외
- 취소 시 현재 작업의 자식 프로세스 정리
- 선택 스트림 크기에 근거한 YouTube 저장 공간 사전 차단
- 로컬 CPU 경로의 전체 작업 완료와 검토 후보 생성

비범위:

- P1~P7의 자막 검색, 이야기 후보 확장, 선택형 GPU와 외부 AI
- 유료 API와 개발자 공용 API 키
- Authenticode 인증서 구매·생성

비범위 항목은 후속 아이디어이며 v0.4.0 출시 차단 사유가 아니다.

## 사용자 변경 사항

- 긴 영상도 전체 파일을 메모리에 올리지 않고 여러 구간으로 나눠 처리한다.
- 이전 작업의 중간 결과가 현재 입력·도구·설정과 맞는지 확인하고, 맞지 않는 중간 결과만 다시 계산한다.
- YouTube 전송 전에 정확한 선택 스트림 크기와 후속 분석 공간을 확인한다. 용량을 안전하게 계산할 수 없거나 공간이 부족하면 전송 전에 이해하기 쉬운 안내를 보여 준다.
- 분석 범위 밖이거나 실제 음량·대화 근거가 없는 후보는 결과에서 제외한다.
- 취소하거나 앱을 종료할 때 현재 작업에서 시작한 하위 프로그램을 정리한다.

## 내부 변경 사항과 체크포인트 호환성

- `media-checkpoint` schema 4에 입력 지문·바이트, 런타임 해시, 언어, 분석 범위와 `rules-v0.4.0-p0` 후보 계산 버전을 기록한다.
- 마지막 정상 파일 세대는 `.prev`로 보존하고 최신 파일이 손상되면 복구한다.
- schema 3 등 호환되지 않는 중간 결과는 자동 재사용하지 않는다. 작업 ID·소스·사용자 설정은 유지하고 미디어 단계부터 다시 계산한다.
- YouTube 메타데이터 확인 결과의 정확한 `format_id` 조합을 실제 전송에 고정한다.
- 정확한 `filesize`가 없거나 출력 상한·계산 범위를 벗어나면 안전하게 중단한다.
- 메타데이터 원문과 stderr 전체는 저장하지 않고 필요한 크기·길이·형식·결과만 기록한다.

## 버그 수정

- 호환되지 않는 체크포인트를 버린 뒤 작업 진행 정보가 앞서 있으면 재개가 멈추던 문제를 수정했다.
- 분석 단계보다 먼저 시작되는 YouTube 내려받기·병합에서 저장 공간 부족을 사전에 막지 못하던 문제를 수정했다.
- 동일 디스크와 분리 디스크의 동시 필요량·순차 필요량을 잘못 계산할 수 있던 초기 구현을 수정했다.
- 디스크 측정 도구가 체크포인트 파일 교체를 방해할 수 있던 검증 환경 문제를 수정했다.

## 보안 수정

- 사용자 URL 검증과 지원 도메인 제한을 유지한다.
- 메타데이터 확인 출력에 상한을 두고 초과하면 자식 프로세스를 정리한다.
- 원시 메타데이터, 전체 stderr, 인증 헤더와 쿠키를 제품 로그에 새로 저장하지 않는다.
- 새 외부 AI·유료 API 전송 경로와 API 키 저장 경로를 추가하지 않았다.
- 저장 공간 확인과 파일 삭제 범위를 현재 작업 경로로 제한한다.
- `npm audit --omit=dev`는 취약점 0개다. 전체 `npm audit`의 high 1건은 Vite→PostCSS의 개발용 `nanoid@3.3.16` 경로이며, 제품 실행 코드는 취약 조건인 사용자 정의 0길이 생성기를 호출하지 않는다.

## PR 형식 자체 리뷰

### 변경 파일

- 제품 코드: YouTube 획득, 저장 공간 계산, 체크포인트·복구, 범위 후보와 취소 경로

## 설치본과 SHA-256

로컬 NSIS 본문은 버전·리소스 확인용이며 공개하지 않는다.

| 로컬 파일 | 크기(bytes) | SHA-256 | 버전 |
|---|---:|---|---|
| `vod-scout.exe` | 15,292,416 | `DB341C2B22D6803964A58D957EE1A658FBB66FCECE205DFFCABA1D1D3AB82703` | 0.4.0 |
| `VOD Scout_0.4.0_x64-setup.exe` | 233,881,664 | `E3CE705383F346FE06AD4410E06E88EBD7758424A06BD37CFA14BC09C128E29B` | 0.4.0 |

- 내장 runtime 28개 재해시 PASS.
- 로컬 환경에는 updater 개인키가 없어 `.sig` 생성 단계는 실행하지 못했다. GitHub Actions에 필요한 두 secret 이름이 있는 것을 확인했으며 값은 읽지 않았다.
- 로컬 앱에는 로컬 체크아웃 경로 문자열이 포함돼 공개 자산으로 사용하지 않는다. release workflow의 경로 치환이 적용된 CI 자산에서 다시 검사한다.
- `SBOM.spdx.json`은 SPDX-2.3, 루트 `vod-scout@0.4.0`, 656 packages로 생성했다.

공개 정본은 태그 Actions가 만든 `VOD.Scout_0.4.0_x64-setup.exe`, `.sig`, `latest.json`과 검증 후 추가하는 `SHA256SUMS.txt`, `SBOM.spdx.json`이다. 실제 크기·SHA-256·Actions run·직접 다운로드 결과는 공개 후 문서 PR에서 이 절과 `BUILD-MANIFEST.md`에 기록한다.

## 알려진 문제

- exact HEAD의 순간 임시 파일 최대값은 미재측정이다.
- YouTube가 일시적으로 403 또는 `Sign in to confirm you're not a bot`를 반환할 수 있다. 로그인 자동화나 쿠키 수집으로 우회하지 않는다.
- Authenticode 부재로 첫 설치에 SmartScreen 경고가 나타날 수 있다. updater minisign 서명은 별도 필수 게이트다.
- 과거 v0.3.2→v0.3.3 제거 프로그램 `DisplayVersion` 잔류의 근본 원인은 확정하지 못했다. v0.4.0 설치 결과는 installer smoke에서 확인한다.

## 롤백 방법

공개 전 문제가 생기면 버전 변경을 병합하지 않고 현재 공개 v0.3.4를 유지한다. 공개 후 문제가 생기면 `v0.3.4` Release와 검증된 설치 파일을 롤백 대상으로 사용한다.

기존 작업 폴더와 사용자 데이터는 삭제하지 않는다. 호환되지 않는 v0.4.0 중간 결과만 다시 계산하고 원본 영상과 작업 설정은 보존한다.
