# VOD Scout v0.4.0 릴리스 기록

상태: **HOLD — 설계·완료 조건 확정, 구현·실제 검증·패키징 전**

계획 정본: [V0.4.0 장시간 최적화·이야기 구간 탐색 계획](V0.4.0-PLAN.md)

설계 검토: [V0.4.0 Oracle 설계 검토 기록](V0.4.0-ORACLE-REVIEW.md)

## 목표와 비범위

v0.4.0은 2~8시간 입력에서 계산량과 저장 공간을 통제하면서 전체 영상 흐름과 수분 단위 이야기 후보를 찾는 버전이다. YouTube 입력은 품질을 통과한 원문 자막을 먼저 사용하고, 부족하거나 의심스러운 구간만 로컬 Whisper로 확인한다. Whisper가 필요하면 실제 시험을 통과한 GPU를 우선 사용하고 실패한 청크만 CPU로 처리한다.

완성 쇼츠 자동 제작, 전체 영상 무조건 정밀 음성 인식, 전체 프레임 OCR, Ollama·대형 로컬 언어 모델, 개발자 공용 API 키, Authenticode 인증서 구매·생성은 범위에 포함하지 않는다.

## 사용자 변경 사항

아직 구현하지 않았다. 계획된 사용자 변경은 다음과 같다.

- `빠르게`, `균형`, `정확하게` 성능 단계와 예상 시간·저장 공간 안내
- YouTube 원문 자막·자동 생성 자막·로컬 음성 인식 출처와 품질 표시
- 현재 작업의 자막·음성 인식 결과 검색과 원본 시각 이동
- 시작·전개·절정·마무리 근거가 있는 이야기 후보와 내부 반응 후보
- `자동(GPU 우선)` 음성 인식과 CPU 자동 전환 상태
- 선택한 경우에만 사용하는 DeepSeek·OpenAI 호환 API 보조 평가

## 내부 변경 사항과 체크포인트 호환성

아직 구현하지 않았다. 다음 계약을 유지한다.

- 입력 지문·길이·도구·모델·언어·분석 범위·자막 개정·GPU 백엔드·후보 계산 버전으로 체크포인트 호환성을 판정한다.
- 자막 원본과 출처·해시, 통합 시간 정보 색인, 전체 저비용 시간축, 이야기 후보와 분석 출처를 분리해 저장한다.
- 전체 PCM·원본 프레임·전체 장시간 텍스트를 한꺼번에 메모리에 올리지 않는다.
- GPU 실패 청크만 CPU로 다시 처리하며 같은 청크를 CPU와 GPU로 동시에 실행하지 않는다.
- 기존 v0.3.2·v0.3.3·v0.3.4 작업 데이터는 보존하고 호환되지 않는 중간 결과만 다시 계산한다.

## 버그 수정

구현 중 실제로 재현하고 수정한 문제만 `docs/DEBUGGING.md`와 함께 기록한다. 현재는 계획 단계이므로 `PENDING`이다.

## 보안 수정

- 자막 확보가 실패해도 로그인·쿠키·나이 제한·봇 확인을 우회하지 않는다.
- 원본 영상·음성·전체 장시간 자막을 외부 API로 보내지 않는다.
- 사용자 API 키는 Windows 보안 저장소에만 보관하고 설정 파일·작업 폴더·체크포인트·로그·내보내기에 남기지 않는다.
- GPU 실행 파일·DLL·모델은 고정된 출처·파일 목록·SHA-256으로 검증한다.
- API·GPU가 없어도 로컬 CPU 규칙 기반 경로로 완료한다.

## PR 형식 자체 리뷰

### 변경 파일

P0~P7 구현 PR별 실제 변경 파일과 최종 통합 목록을 기록한다.

### 위험과 회귀 가능성

- 잘못된 언어·자동 번역·누적 중복 자막을 원문으로 채택할 위험
- 자막이 있는 영상에서 조용하지만 중요한 사건을 저비용 신호가 누락할 위험
- 체크포인트가 다른 자막 개정·모델·장치 결과를 잘못 재사용할 위험
- GPU 메모리 부족과 자식 프로세스 실패 뒤 작업 전체를 잃을 위험
- 외부 API로 필요 이상 정보나 인증값이 전송될 위험
- 장시간 입력에서 임시 파일·메모리·후보 수가 계속 증가할 위험

### 발견 사항과 조치

각 구현 PR과 최종 릴리스 리뷰에서 `PASS`, `HOLD`, `BLOCKED`로 기록한다. 미확인 하드웨어·입력·외부 서비스는 PASS로 표시하지 않는다.

## 설치본과 SHA-256

아직 설치본을 만들지 않았다. 버전 정본이 모두 `0.4.0`으로 일치하는 exact merged commit에서 빌드한 뒤 설치 EXE, 핵심 바이너리, GPU 묶음, 모델, updater 서명, 체크섬과 SBOM을 `BUILD-MANIFEST.md`와 함께 기록한다.

## 알려진 문제

- 성능 측정 전에는 “8시간 완전 지원”, “GPU 지원”, “이야기 구간 정확 탐지”라고 표시할 수 없다.
- 자막 품질 임계값과 이야기 후보 합격선은 여러 실제 영상의 사람이 표시한 기준 구간을 확보하기 전까지 `HOLD`다.
- Authenticode 인증서가 없으면 SmartScreen 경고가 표시될 수 있으며 인증서를 구매하거나 만들지 않는다.

## 롤백 방법

릴리스 뒤 문제가 발견되면 검증된 직전 공개 설치본으로 되돌린다. 기존 작업 폴더와 `current-job.json`은 삭제하지 않는다. 새 스키마는 읽기 전 백업 또는 마지막 정상 세대를 보존하고, 이전 버전이 읽을 수 없는 중간 결과만 명시적으로 다시 계산한다. 실제 직전 버전과 설치 파일 SHA-256은 v0.4.0 빌드 시점에 고정한다.
