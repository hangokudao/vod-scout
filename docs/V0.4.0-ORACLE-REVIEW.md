# VOD Scout v0.4.0 Oracle 설계 검토 기록

검토일: 2026-08-05
상태: **독립 검토 3건 완료 · 코드 구현 전 HOLD**

이 문서는 VOD Scout v0.3.3 저장소 전체와 v0.4.0 계획을 대상으로 수행한 Oracle 자문을 공개 저장소에 남기기 위한 요약 기록이다. Oracle 답변은 자문 자료이며, 아래 최종 결정은 Codex/Sol이 실제 코드와 릴리스 증거를 다시 대조한 결과다.

상세 구현 순서와 완료 조건은 [V0.4.0 계획](V0.4.0-PLAN.md)을 따른다.

## 검토 범위와 증거

- 검토 기준 worktree HEAD: `ed1b52eb484c349a3e4ac326795351b1cfbcd4a8`
- 기준 공개 브랜치: `origin/main` `cf40ead39d38379f767e49d1bae5c9e29bb55917`
- 입력: `AGENTS.md`, 제품·릴리스·테스트 문서, React UI, Rust/Tauri 수집·저장·분석 경로 등 32개 파일
- 각 요청의 입력 크기: 약 13.4만 토큰
- 방식: 저장소 성능 감사, 자막 우선 설계 반대 검토, 이야기 후보 품질 설계를 서로 독립된 브라우저 자문으로 실행
- 요청 모델 메타데이터는 `gpt-5.6-sol`, 브라우저 탭 표시는 `Pro`였다. Oracle 산출물의 모델 선택 검증 필드는 `verified=no`였으므로 정확한 서버 측 모델 식별은 `HOLD`다.

Oracle 전문은 로컬 세션 산출물로 보존하고 공개 저장소에는 복사하지 않는다. 원본을 식별할 수 있도록 다음 해시만 기록한다.

현재 저장소는 v0.3.3 범위에서 무조건 최적화가 나쁜 구조가 아니다. 가장 큰 문제는 계산량 자체가 아니라, 빠른 분석이 계산을 줄이면서 전체 시간대의 음성·대화 근거를 함께 잃고도 전체 영상 후보를 순위화한다는 점이다.

## 코드에서 다시 확인한 우선 문제

### P0 · 다음 기능보다 먼저 해결

1. **빠른 분석의 근거 범위와 후보 순위 범위가 다르다.**
   - 빠른 분석은 전체 길이의 20%를 30~120분 범위로 나눠 음성을 처리한다.
   - 후보 생성은 전체 영상 길이에서 15초 간격의 창을 만든다.
   - 선택하지 않은 시간대에는 음량·대화 근거가 없고 채팅 영역 움직임만 남는다.
   - 2시간 영상에서는 10분짜리 사건이 선택 구간 사이에 완전히 들어가 누락될 수 있다.

2. **체크포인트 호환성 판정이 출처 기록보다 약하다.**
   - [체크포인트 읽기](../src-tauri/src/media.rs)는 스키마·경로 문자열·분석 방식·범위만 비교한다.
   - 이미 기록하는 입력 지문, FFmpeg·Whisper·모델 해시, 언어, 후보 계산 버전은 체크포인트 허용 조건에 쓰지 않는다.
   - 같은 경로의 영상이나 도구·모델이 바뀌었을 때 예전 중간 결과를 현재 결과처럼 재사용할 가능성이 있다.

3. **저장 공간은 작업 전 차단하지 않고 작업 후 측정한다.**
   - 승인된 8시간 53분 작업의 최종 용량은 7,097,358,568 bytes다.
   - 영상·음성 병합 중 순간 최대 임시 용량은 아직 `HOLD`다.
   - 선택한 스트림 크기, 병합 여유 공간, 체크포인트·미리보기 공간을 합친 사전 확인이 필요하다.

### P1 · 정확성과 복구 위험

1. **범위 지정 분석이 범위 밖 후보를 만들 수 있다.**
   - 음성·채팅 처리는 지정 범위로 제한하지만 [후보 생성 호출](../src-tauri/src/media.rs)은 전체 영상 길이를 넘긴다.
   - 근거가 없는 창을 제외하는 최소 조건도 없다.

2. **취소 보호는 있으나 전체 단계 감독은 미완성이다.**
   - Windows Job Object와 자식 프로세스 `kill + wait`는 구현돼 있다.
   - 실제 YouTube 작업이 1분 이상 `worker 종료 요청`에 머문 제보는 `HOLD`다.
   - 후보·맥락 미리보기 FFmpeg는 작업 취소 상태와 연결되지 않은 별도 `AtomicBool(false)`를 사용한다.

3. **중간 파일 교체가 마지막 정상 세대를 보존하지 않는다.**
   - 일부 체크포인트·음성 텍스트 파일은 임시 파일을 쓴 뒤 기존 파일을 삭제하고 이름을 바꾼다.
   - 삭제와 이름 변경 사이에 종료되면 마지막 정상 파일을 잃을 수 있다.

4. **현재 후보 구조로는 이야기를 표현할 수 없다.**
   - 최대 45초, 15초 간격, 최대 8개, 앞뒤 약 15초 맥락 구조다.
   - 긴 이야기 후보와 그 안의 짧은 반응 후보를 별도 자료형으로 분리해야 한다.

### P2 · 장시간 입력에서 커질 효율 문제

- 청크 완료마다 전체 체크포인트와 전체 음성 텍스트를 다시 직렬화해 누적 쓰기량이 커진다.
- 각 15초 창이 음량·문장·채팅 배열을 반복 검색해 영상이 길어질수록 후보 계산 비용이 불필요하게 증가한다.
- 채팅 신호는 오른쪽 38%의 화면 변화이며, 실제 채팅 내용이나 채팅 영역임을 확인한 값이 아니다.
- 현재 한국어 고정 필터는 한글이 없고 영문자가 8자 이상인 문장을 제거해 혼합 언어·게임 이름을 손상할 수 있다.

## 확정 설계

최종 설계 명칭은 **자막 탐색·품질 검증·출처 보존형 단계적 혼합 구조**로 한다.

```text
YouTube 주소
→ 공개 자막 트랙 목록 확인
→ 제작자 원문 자막 우선, 없으면 자동 생성 원문 자막 선택
→ 원본 자막 파일과 해시·출처 저장
→ 자막 범위·중복·언어·시간 정렬 품질 검사
→ 전체 영상 저비용 음성·장면·채팅 움직임 색인
→ 고정 시간 구간으로 전체 흐름 정리
→ 규칙 기반 이야기 후보와 내부 반응 후보 생성
→ 자막 공백·의심 구간·상위 후보 경계만 로컬 Whisper로 확인
→ 사람이 검토
→ 선택한 경우에만 DeepSeek·OpenAI 호환 API 보조 평가
```

### 자막 선택과 대체 처리

1. 제작자가 작성한 원문 자막
2. 자동 생성된 원문 자막
3. 자막이 없거나 품질 검사에 실패하면 로컬 Whisper

자동 번역 자막, `live_chat`, 실제 오디오 언어와 연결할 수 없는 트랙은 기본 이야기 색인으로 사용하지 않는다. 자막 확보가 실패해도 영상 다운로드와 현재 로컬 분석 경로는 계속돼야 한다. 로그인·쿠키·나이 제한·봇 확인 우회는 지원 범위에 넣지 않는다.

### 전체 시간대 근거

- 자막은 주제·검색어·사건 연속성에 사용한다.
- 전체 시간대의 음성 존재·음량·침묵·장면 변화는 자막과 별도로 계산한다.
- 채팅 영역 움직임은 전체 화면 변화와 비교하고, 실제 채팅 영역으로 확인되지 않았으면 일반 화면 움직임으로 표시한다.
- 원본 프레임과 전체 PCM은 누적 저장하지 않는다.

### 이야기 후보

- 전체 영상을 고정된 짧은 시간 구간으로 나눠 안정적인 ID를 부여한다. Oracle이 제안한 30초는 첫 시험값이며 실제 기준 영상 측정 전까지 `HOLD`다.
- 주제 연속성, 침묵·장면 경계, 음량·대화·채팅 변화로 수분 단위 이야기 후보를 만든다.
- 기존 15~90초 반응 후보는 이야기 후보 안의 절정 또는 짧은 편집 후보로 유지한다.
- 처음부터 중간 결과를 8개로 제한하지 않고, 이야기 단위 중복 제거 후 최종 검토 수를 제한한다.

### Whisper 역할

- 사용 가능한 자막이 있으면 자막 공백, 의심 구간, 상위 이야기의 시작·절정·마무리 주변만 확인한다.
- 자막이 없는 입력에서 이야기 탐지를 약속하려면 침묵을 제외한 전체 음성 구간을 순차 처리해야 한다.
- 현재 20% 빠른 분석은 반응 후보를 빨리 찾는 별도 모드로 유지하되, 이야기 누락이 없다고 표시하지 않는다.
- 고정된 표본 수·품질 임계값은 여러 실제 영상으로 비교하기 전까지 `HOLD`다.

### 선택형 사용자 API

규칙 기반 결과가 먼저 완성돼야 한다. API는 기본적으로 꺼져 있고 원본 영상·음성·전체 장시간 자막을 보내지 않는다.

독립 검토 사이에는 API 역할에 의견 차이가 있었다. 성능 감사는 기존 후보 재정렬만 허용했고, 품질 설계는 고정 시간 구간 ID의 선택·병합까지 허용해야 이야기 누락을 보완할 수 있다고 판단했다. 최종 결정은 다음과 같다.

- 첫 구현에서는 로컬 이야기 후보 재정렬·요약부터 검증한다.
- 품질 자료가 API의 범위 조정 필요성을 보여 주면, API가 이미 존재하는 연속 구간 ID만 선택·병합할 수 있게 확장한다.
- API는 타임코드, 존재하지 않는 ID, 떨어진 구간을 하나의 이야기로 만들 수 없다.
- 모든 응답은 로컬에서 다시 검증하고 실패하면 규칙 기반 결과를 유지한다.

## 검증 게이트

다음은 수치 보정 없이도 통과해야 한다.

- 지정 범위 밖 후보 0개
- 입력·도구·모델·후보 계산 방식이 바뀐 뒤 낡은 체크포인트 재사용 0개
- 취소 완료 뒤 관련 자식 프로세스 0개
- 현재 출처 기록으로 과거 중간 결과를 덮어쓰는 경우 0개
- 자막 확보 실패 시 기존 로컬 경로 완료
- 네트워크가 끊겨도 이미 확보한 미디어·자막으로 분석 완료
- API를 끈 상태에서 외부 AI 요청 0개
- API 실패 뒤 규칙 기반 결과 보존
- 전체 PCM·원본 프레임 누적 없음

이야기 품질은 `StoryHit@1/3/8`, 시작·끝 오차, 시간 구간 겹침, 조용한 사건 재현율, 큰 반응만 있고 이야기는 아닌 구간의 오탐, 사용자가 첫 채택까지 검토한 총 시간을 기록한다. 합격 수치는 기준 영상 묶음을 만든 뒤 고정한다.

## 문서 결정

- Oracle 원문 전체는 생성 산출물이므로 저장소에 넣지 않는다.
- 이 문서와 [V0.4.0 계획](V0.4.0-PLAN.md)을 v0.4.0 설계 정본으로 사용한다.
- 검색어 기능은 같은 시간 정보 자막 색인을 재사용하는 P1 기능으로 포함한다.
- Oracle 검토 당시에는 GPU 음성 인식을 OCR·채팅 영역 자동 탐색과 함께 오프라인 이야기 품질 게이트 뒤에 두었다. 이후 사용자 제품 결정으로, 불필요한 음성 인식을 줄이는 P0~P3 뒤 선택형 Whisper를 구현하는 P4에 GPU 우선 실행과 CPU 자동 전환을 함께 넣는다. OCR·채팅 영역 자동 탐색과 선택형 API는 기존 후순위 게이트를 유지한다.
