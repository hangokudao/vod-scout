- 정상 완료
- 제어된 실패
- 중간 충돌과 재개
- heartbeat 정지 감지
- 잘못된 JSON 이벤트 거부

### 실제 미디어 무창 통합

1. 11초 MP4 → ffprobe JSON
2. FFmpeg → 16 kHz mono WAV
3. whisper.cpp base → 실제 SRT 문장
4. Rust → RMS·후보 생성
5. 체크포인트 저장

### 제품 경로 무창 E2E

- Tauri `create_job/start_job` 실제 호출
- React DOM이 검토 화면으로 전환
- 실제 Whisper 문장과 채팅 움직임 점수가 후보에 포함
- 후보 겹침과 알려진 영어 반복 환각 0개
- 후보 영상 프록시 생성과 `<video>.readyState >= 1`
- 작업 용량, UTF-8 BOM CSV, 작업 삭제
- 영상 처리 중 `cancel_job`
- 10초 안에 `CANCELLED`
- 같은 작업 재개 후 `REVIEW_READY`
- 취소 활동, 음성 인식 결과 5개 구간, 체크포인트 보존
- 부모 앱 강제 종료 시 관찰 중인 ffprobe/FFmpeg/Whisper 자식 PID 소멸

### 실제 한국어 장시간 E2E

- 1시간 5분 29초 원본 → 10분 청크 7개
- 중간 체크포인트 3/7에서 재개 → `REVIEW_READY`, 13/13
- 음성 인식 결과 702개 구간, 채팅 움직임 785포인트, 후보 8개
- 후보 시간 겹침과 알려진 영어 반복 환각 0개
- ETA 표시, 플레이어 준비, CSV·용량·삭제 확인

### 실제 YouTube 무창 E2E

- 공개 단일 영상 URL → yt-dlp + Deno → 최대 720p 로컬 파일
- 다운로드 진행률 → `acquisition.json`과 완료 영상 저장
- 다운로드 직후 취소 → `CANCELLED` → 같은 작업 재개
- ffprobe·FFmpeg·Whisper → `REVIEW_READY`, 실제 음성 인식 결과와 후보 생성
- 삭제·사용 불가 영상 → 사용자 오류와 yt-dlp 진단 분리

무창 E2E에서만 `VOD_SCOUT_HEADLESS_E2E`와 로컬 CDP 포트를 사용한다. 배포 앱은 디버그 포트를 열지 않는다.

### 실제 취소·재개

- YouTube 내려받기, FFmpeg 추출, Whisper 음성 인식 단계에서 각각 취소한다.
- 취소 요청부터 worker·자식 프로세스 종료·체크포인트 저장·`CANCELLED` 반영까지 단계별 시간을 기록한다.
- 실제 작업이 60초 이상 `취소 중…`에 머물면 `HOLD`다.
- 취소 완료 뒤 관련 자식 프로세스가 0개이고 같은 작업이 마지막 정상 체크포인트부터 재개되는지 확인한다.
- 강제 종료는 현재 작업의 확인된 프로세스 트리에만 적용되고 다른 앱이나 다른 작업 프로세스를 종료하지 않는다.

### updater와 측정

- 공개 v0.3.3 설치본에서 v0.3.4를 찾아 설치하고 재실행한다.

- YouTube 병합 중 열린 출력 파일을 포함해 내려받기·분석 WAV·미리보기·최종 작업 용량의 최대값을 기록한다.

## v0.4.0 최적화 측정

### O0 기준선

같은 입력을 v0.3.3 CPU 경로로 실행해 다음 값을 기록한다.

- 원본 길이·해상도·코덱·파일 크기
- CPU·메모리·GPU·저장 장치
- 분석 방식과 Whisper 모델
- 전체 처리 시간과 각 단계 처리 시간
- 피크 메모리와 GPU 메모리
- 임시 파일 최대 크기와 최종 작업 용량
- 음성 인식 구간·이야기 후보·반응 후보 수
- 취소·재개와 남은 자식 프로세스

기준선을 측정하기 전에는 성능 개선률이나 합격 수치를 확정하지 않는다.

### YouTube 자막·검색

- 제작자가 작성한 원문, 자동 생성 원문, 자동 번역, `live_chat`, 다른 언어 트랙이 함께 있을 때 제작자 원문을 우선한다.
- 제작자 원문이 없으면 실제 오디오 언어와 일치하는 자동 생성 원문을 선택하고 자동 번역·`live_chat`·잘못된 언어 트랙은 기본 색인에서 제외한다.
- 누적 표시 자동 자막의 반복 문구는 정리하되 실제 반복해서 말한 내용은 보존한다.
- 자막 범위·긴 공백·타임코드 순서·언어·반복 비율과 소량의 로컬 음성 확인으로 품질 상태를 기록한다.
- 자막 목록 확인·다운로드·해석·품질 검사가 실패해도 로컬 Whisper 경로로 작업을 완료한다.
- 미디어와 자막을 확보한 뒤 네트워크를 끊어도 분석·검색·원본 시각 이동을 완료한다.
- 검색 결과에 문장, 원본 시각, 자막 또는 로컬 음성 인식 출처를 표시하고 해당 시각으로 이동한다.
- 작업 재개 시 같은 자막 개정과 파일 해시를 재사용하고 명시적으로 새로 확인한 경우에만 개정이 바뀐다.

### 하드웨어 경로

| 경로 | 확인 내용 |
|---|---|
| CPU 전용 | 현재 기준 결과와 체크포인트 호환성 |
| 지원 GPU | 실제 GPU 백엔드 로드와 시험 음성 인식, 장치·메모리 기록, 같은 입력 완료 |
| GPU 메모리 부족 | 실패 청크만 CPU로 재처리 |
| 지원하지 않는 GPU | 오류 대신 CPU 경로 선택과 설명 표시 |
| 드라이버 오류 | 자식 프로세스 정리, 체크포인트 보존, CPU 재개 |

실제로 시험하지 않은 장치 조합은 지원 목록에 넣지 않는다.

- 기본 장치 `자동(GPU 우선)`에서 GPU 백엔드가 실제로 로드됐다는 로그와 실행 기록이 있을 때만 GPU PASS로 판정한다.
- CPU와 GPU가 같은 청크를 동시에 처리하지 않는지 PID·로그·체크포인트로 확인한다.
- CPU와 GPU 결과가 같은 시간 정보·체크포인트 형식을 사용하고 GPU 실패 뒤 기존 완료 청크를 다시 계산하지 않는지 확인한다.

### 1~2시간 회귀

- 말이 많은 방송, 조용한 방송, 게임 화면이 자주 바뀌는 방송을 분리해 시험
- 빠르게·균형·정확하게 설정별 자원과 결과 비교
- CPU와 지원 GPU의 처리 시간·결과 차이 기록
- 중간 취소와 앱 강제 종료 후 마지막 완료 단계부터 재개
- 디스크 공간 부족을 시작 전과 실행 중에 각각 처리
- 사람이 표시한 이야기 구간과 후보의 겹침·시작 오차·끝 오차 기록

### 8시간 빠른 분석

1. 실제 8시간 영상 또는 사용자가 승인한 동등한 입력을 사용한다.
2. 전체 저비용 색인이 처음부터 끝까지 만들어지는지 확인한다.
3. 음성 인식 예산이 영상의 한 시간대에만 몰리지 않는지 확인한다.
4. 처리 시간, 피크 메모리, GPU 메모리, 임시 파일, 최종 용량을 기록한다.
5. 취소·재개와 앱 종료·재실행을 각각 확인한다.
6. 완료 뒤 남은 FFmpeg·Whisper·GPU 자식 프로세스가 없어야 한다.
7. 전체 PCM·원본 프레임이 작업 폴더에 누적되지 않아야 한다.
8. 후보 타임코드와 시작·절정·마무리 근거가 원본과 일치해야 한다.

### 이야기 구간 품질

- 기준 영상마다 사람이 하나 이상의 시작·전개·절정·마무리 구간을 표시한다.
- 시스템이 제안한 이야기 후보와 사람 구간의 겹침, 시작 오차, 끝 오차를 측정한다.
- 이야기 후보 안에서 15~90초 반응 후보가 실제 핵심 순간을 포함하는지 별도로 판정한다.
- 반응이 크지만 맥락이 없는 후보와 조용하지만 중요한 후보를 구분해 오류 유형을 기록한다.
- 합격선은 기준 자료를 충분히 확보한 뒤 고정하며 단일 영상 결과로 일반화하지 않는다.

### 선택형 사용자 API

- API 기능을 끈 상태에서 외부 요청이 없고 기존 규칙 결과가 동일하게 완료되는지 확인한다.
- API 키가 설정 파일·작업 폴더·체크포인트·로그·내보내기·오류 메시지에 남지 않는지 확인한다.
- 원본 영상·음성·전체 음성 인식 결과가 아니라 선택한 상위 후보의 음성 인식 결과와 신호 요약만 전송되는지 확인한다.
- 전송 전에 제공처·모델·후보 수·예상 토큰과 비용·작업당 비용 한도를 표시하고 동의를 받는지 확인한다.
- 잘못된 키, 연결 실패, 시간 초과, 잘못된 응답, 비용 한도 초과에서 규칙 기반 결과와 사용자 판정이 보존되는지 확인한다.
- 응답에 없는 후보 ID나 새 타임코드가 포함되면 거부하고 기존 후보만 재정렬하는지 확인한다.
- 실제 유료 호출 검사는 전용 시험 키와 낮은 비용 한도를 사용하며 키와 인증 헤더를 검증 산출물에 남기지 않는다.

위 자막·이야기·사용자 API 항목은 v0.4.0 이후 보류된 확장 기능의 검증 계약이다. v0.5.0 완료 조건에는 포함하지 않는다.

## v0.5.0 품질·작업 대기열 검증

### 자동 테스트

- 한 글자·짧은 단어·짧은 문장의 비정상 반복과 `�`가 포함된 음성 인식 결과를 불확실로 판정한다.
- 실제 반복 발언, 웃음, 감탄과 노래를 반복 오류로 일괄 제거하지 않는다.
- 불확실한 문장을 후보 제목에 사용하지 않지만 원본 결과와 오디오·화면 근거는 보존한다.
- 후보 제한 8·20·30이 작업별로 저장·복원되고 후보가 부족할 때 개수를 억지로 채우지 않는다.
- 작성자 ID·고유 참여자 수·메시지 수 없이 현재 VOD의 고정 채팅 영역 움직임을 내부 평소 분포와 비교한다.
- 채팅 신호가 없거나 한 번의 화면 변화만 있을 때 채팅만으로 후보를 만들지 않는다.
- 일반 문장과 이모티콘을 구분하지 않은 상태에서 구분 결과를 생성하지 않는다.
- 유효한 고정 영역 표본이 부족하면 `확인 가능한 채팅 영역 움직임 없음`으로 처리하고 나머지 신호를 다시 맞춘다.
- 대기 순서 저장·복원, 시작하지 않은 작업의 순서 변경, 실행 작업 최대 1개를 확인한다.
- 작업 하나의 `FAILED`·`CANCELLED`가 다음 대기 작업의 시작을 막지 않는다.
- 실패·취소 작업을 자동 재시작하지 않고 사용자가 요청한 재시작만 허용한다.
- 앱 강제 종료 뒤 실행 작업을 `INTERRUPTED`로 복원하고 사용자 재개·취소 전에는 해당 작업이나 다음 작업을 자동 시작하지 않는다.
- 두 앱 인스턴스가 같은 대기열을 열어도 한 인스턴스만 실행권을 얻고, 원자적 대기열 저장이 손상되면 직전 정상본을 읽는다.
- GPU 시험 실패 시 CPU를 선택하고, 실행 중 GPU 실패 청크는 CPU로 한 번만 다시 처리한다.
- GPU 실패와 CPU 대체 처리 상태를 저장해 앱 재실행 뒤 GPU부터 다시 시작하지 않는다. CPU 처리도 실패하면 같은 청크를 다시 호출하지 않고 작업을 `FAILED`로 끝낸다.
- 제한적 병렬 처리 기본값은 꺼짐이며 자원 조건 실패 뒤 순차 처리로 한 번만 전환한다. 전환 상태는 앱 재실행 뒤에도 유지한다.
- 사용자 행동 한 번이 후보 재분석 실행 ID 하나만 만들고 완료·실패가 재분석을 자동 호출하지 않는다.
- v0.4.0 작업은 열기만 해서는 후보를 재계산하지 않는다. 후보 수 변경·수동 재분석은 새 개정을 만들고 동일한 후보 ID의 판정만 이어받으며 이전 개정과 정상본을 보존한다.
- 품질 조건별 표시 전용·순위 하락·무효 후보 제외 효과와 게임·노래·웃음·조용한 대화 예외를 각각 검사한다.

### 실제 제품 흐름

1. 지원 영상 3개를 등록해 기본 순서대로 `대기 → 분석 중 → 검토 준비`가 이어지는지 확인한다.
2. 첫 작업 결과를 검토하는 동안 두 번째 작업 진행 상태와 세 번째 작업 대기를 확인한다.
3. 두 번째 작업을 제어된 실패로 끝내고 세 번째 작업이 자동으로 시작되는지 확인한다.
4. 앱을 강제 종료한 뒤 마지막 완료 체크포인트, 대기 순서, 후보 판정과 작업별 설정이 복원되는지 확인한다.
5. 대기 작업 취소와 실행 작업 취소가 다른 작업 폴더·체크포인트를 변경하지 않는지 확인한다.
6. 후보 8·20·30 설정에서 원본 범위, 중복 제거, 판정 복원과 UI 반응성을 확인한다.
7. 시작 전 대기 작업과 종료 상태 작업은 즉시 삭제하고, 실행 작업은 취소→자식 프로세스 0개→종료 상태 저장→폴더 삭제 완료→대기열 참조 제거 순서를 따른다. 개별·전체 삭제가 실패하면 참조와 `삭제 실패` 상태를 유지하고 다른 작업을 바꾸지 않는지 확인한다.
8. v0.5.0 후보 개정을 만든 뒤 이전 v0.4.0 후보·판정을 확인하고 보존한 정상본으로 롤백할 수 있는지 확인한다.

### 품질 비교

- 사용 권한과 보관 범위를 확인한 저스트채팅·게임 VOD로 v0.4.0과 v0.5.0 결과를 비교한다.
- 깨진 음성 인식 결과가 제목에 노출된 수, 중복 후보 수, 사람이 채택한 후보 수와 검토 시간을 기록한다.
- 현재 VOD의 고정 채팅 영역 표본이 부족한 입력과 내부 평소 분포보다 움직임이 증가한 입력을 구분한다.
- 채팅 영역 움직임 증가만 있고 오디오·말하기·화면 근거가 없는 구간이 상위 후보를 독점하지 않는지 확인한다.
- 기준 영상이 없거나 사람이 판정하지 못한 결과는 `HOLD`로 두고 정확도 수치를 만들지 않는다.
- 기능 PASS는 품질 조건의 고정 효과와 예외가 계약대로 동작할 때 판정한다. 객관 지표가 악화되거나 사람이 채택한 비율·검토 시간 개선이 확인되지 않으면 품질 개선을 주장하지 않고 측정 결과만 기록한다.

### GPU·CPU와 자원

| 환경 | 확인 내용 |
|---|---|
| CPU 전용 | GPU 오류 없이 전체 작업 완료 |
| 지원 GPU | 시험 실행·백엔드 로드·결과 생성 뒤 GPU 사용 |
| 지원하지 않는 GPU | CPU 선택과 이해할 수 있는 안내 |
| GPU 메모리 부족·드라이버 오류 | 실패 청크 CPU 1회 처리, 기존 완료 청크 보존 |
| GPU와 CPU 모두 실패 | 작업 `FAILED`, 자동 재시도 없음, 다음 대기 작업 진행 |

- 같은 실제 입력에서 변경 전후 단계별 시간, CPU, 메모리, 디스크와 자식 프로세스 수를 기록한다.
- 분석 중 취소·화면 이동·현재 상태 확인이 가능하고 종료 뒤 관련 자식 프로세스가 0개인지 확인한다.
- 경고 자원 기준에서는 안내만 하고, 강제 기준을 넘으면 현재 작업 소유 자식만 종료해 체크포인트와 실패 이유를 보존한 뒤 `FAILED`로 끝내며 자동 재시작하지 않는지 확인한다.
- 순차 처리와 제한적 병렬 처리의 총시간·피크 자원을 같은 입력 묶음으로 비교한다. 측정 통과 시에만 선택 기능을 제공하고, 이득보다 렉·메모리·실패가 크면 미제공으로 평가를 완료한다.

### 실제 화면

- 1280px 이상, 900~1279px, 899px 이하에서 대기열·후보 수 설정·품질 경고가 겹치지 않는다.
- `음성 인식 결과 불확실`, `채팅 영역 움직임`, GPU→CPU 전환과 실패 이유가 색상만이 아니라 문구로 구분된다.
- 키보드와 화면 버튼으로 대기 작업 이동, 취소, 실패 작업 재시작과 후보 검토를 수행할 수 있다.

## 최적화 회귀 금지 조건

다음 중 하나라도 발생하면 더 빠르더라도 최적화 PASS가 아니다.

- 기존 작업이나 완료 체크포인트 손상
- 취소 뒤 자식 프로세스 잔존
- GPU 실패 뒤 작업 전체 초기화
- 사용자 동의 없는 외부 전송 또는 비용 발생
- 같은 입력·설정에서 후보 타임코드가 실행마다 불안정하게 변경
- 임시 파일 또는 메모리가 입력 길이에 비례해 제한 없이 누적
- CPU 전용 PC에서 핵심 분석 불가
- 실패·취소 작업, 후보 재분석 또는 GPU·병렬 대체 처리가 자동으로 반복됨
