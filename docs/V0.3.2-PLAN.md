# VOD Scout v0.3.2 구현·검증 계획

상태: **구현 완료 · RC 보안·설치 게이트 PASS**
릴리스 성격: 보안 기준선 복구 + 장시간 분석 비용 절감 + 재현 가능한 검증

## 목표

1. 전달받은 HIGH·MEDIUM 보안 문제를 해결하고 새 설치본의 신뢰 경계를 만든다.
2. 장시간 VOD에 `빠른 분석`, `구간 지정`, `전체 정밀 분석`을 제공한다.
3. yt-dlp·Whisper·ROI·분석 옵션과 단계별 체크포인트 출처를 기록한다.
4. 실제 1~2시간 YouTube 영상과 8시간 빠른 분석에서 처리 시간·메모리·디스크·재개를 검증한다.
5. 변경을 private staging PR로 검증한 뒤 public 정본 저장소와 Windows 설치 EXE GitHub Release를 함께 공개한다.

## 비범위

- GPU 전사 공식 지원
- 구간별 채팅 영역 자동 탐색과 OCR
- 개인화 학습과 LLM 재순위
- 완성 쇼츠 렌더링
- Authenticode 인증서 구매

코드 서명이 없으면 SmartScreen 경고와 미서명 상태를 명시하고 체크섬·SBOM·소스 태그를 제공한다. 공개 소스와 설치 EXE 배포 자체는 v0.3.2 범위다.

## 사용자 분석 모드

### 빠른 분석 — 권장

8시간 전체를 Whisper에 넣지 않는다.

1. 기본 전사 예산은 `min(120분, max(30분, 전체 길이의 20%))`로 제한한다. 8시간이면 약 96분의 구간이 대상이다.
2. 10분 청크를 방송 전체 시간대에 고르게 분산해 특정 시간대만 보는 편향을 줄인다.
3. 전체 영상의 화면 오른쪽을 15초 간격 저해상도로 비교해 채팅 움직임을 보조 신호로 계산한다.
4. 선택된 청크에서 1초 오디오 에너지와 한국어 전사를 계산하고 채팅 신호와 결합한다.
5. 후보는 원본 절대 타임코드를 유지한다. 사용자는 놓친 시간대를 `구간 지정`으로 추가 분석할 수 있다.

장점: Whisper 입력량과 처리 시간을 크게 줄인다.  
한계: 음량 변화가 적은 조용한 티키타카를 놓칠 수 있으므로 “전체 분석과 같은 정확도”라고 표시하지 않는다.

### 구간 지정

- 사용자가 `HH:MM:SS` 시작·끝을 입력한다.
- 원본 파일을 실제로 자르거나 덮어쓰지 않고 선택 범위만 전사·분석한다.
- 후보·CSV·플레이어 시간은 원본 영상 기준이다.
- 2시간 단위 등 여러 범위를 별도 작업으로 처리할 수 있다.
- 시작≥끝, 음수, 원본 길이 초과를 백엔드에서 거부한다.

### 전체 정밀 분석

- 현재 v0.3.1처럼 선택 범위 전체를 10분 청크로 전사한다.
- 가장 오래 걸리지만 조용한 대화 구간 누락 위험이 가장 낮다.
- 8시간 정밀 분석은 v0.3.2에서 지원을 과장하지 않고 별도 안정성 결과가 PASS일 때만 문구에 반영한다.

## 내부 데이터와 체크포인트

작업마다 `pipeline-provenance.json`을 저장한다.

- 앱 버전과 빌드 식별자
- 원본 경로를 직접 공개하지 않는 파일 크기·수정 시각 기반 fingerprint
- 분석 모드와 시작·끝·전사 예산
- FFmpeg·ffprobe·Whisper·모델·yt-dlp·Deno 실제 SHA-256과 버전
- CPU/GPU backend, thread 수, Whisper 옵션
- 채팅 ROI와 샘플 간격, detector 버전
- 후보 ranker 버전과 가중치
- 단계별 시작·완료·fallback·실패

무효화 규칙:

- Whisper 모델·옵션·backend 변경 → 전사와 모든 후속 단계 재계산
- 분석 범위·빠른 분석 예산 변경 → 해당 범위 신호·전사·후보 재계산
- 채팅 ROI·샘플링 변경 → 채팅 신호와 후보 순위 재계산
- ranker 변경 → 후보 순위만 재계산
- yt-dlp 변경 → 완료 영상이 없을 때만 acquisition 재실행

CPU와 향후 GPU 청크, 이전 고정 ROI와 새 ROI 결과를 섞지 않는다.

## RC 단계

### RC0. private Git 기준선

`docs/GIT-PRIVATE-REPOSITORY-PLAN.md` G0~G6를 수행한다. 현재 파일을 secret scan한 뒤 `v0.3.1 security-hold baseline`을 `hangokudao/vod-scout-dev` private 원격에 보존한다.

완료 조건: private·SHA read-back, 금지 파일 0개, `security/v0.3.2` 브랜치.

### RC1. 보안 수정

- SEC-001: 사용자 전용 설치 ACL
- SEC-002: 도구·모델 runtime 해시 검증과 설치 해시 연결
- SEC-003: 모든 작업 목록·용량·선택/전체 삭제
- SEC-004: 자식 환경 최소화와 FFmpeg 프로토콜 제한
- SEC-005~006: CSV 수식·저장 경계 수정
- SEC-007: release 빌드 경로·사용자명 제거
- SEC-008: Asset Protocol을 미리보기 MP4로 축소
- SEC-009~010: 매 빌드 재해시와 ZIP 경로 검증

완료 조건: `docs/SECURITY-AUDIT-2026-08-02.md`의 v0.3.2 보안 게이트 PASS. HIGH가 남으면 다음 RC와 패키징 금지.

### RC2. provenance와 분석 범위

- 새 작업 입력에 분석 모드·시작·끝 추가
- 체크포인트 schema와 stage fingerprint 추가
- 범위 변경 시 올바른 단계만 무효화
- 경과 시간·ETA를 분석 대상 길이 기준으로 계산
- validation JSON에 CPU·메모리·디스크·PID·도구 버전 기록

완료 조건: 이전 작업을 잘못 재개하지 않고, 동일 옵션은 정상 재개하며, 범위 타임코드가 원본과 일치.

### RC3. 빠른 분석

- 전체 시간대 분산과 전사 예산을 적용한 청크 선택
- 전체 영상의 저비용 채팅 움직임 스캔
- 선택 구간만 오디오 추출·Whisper 전사
- 후보 근거에 `빠른 분석`과 분석된 범위를 명시
- 필요하면 선택 후보 주변을 정밀 분석하는 재실행 경로 제공

완료 조건: 결정론 fixture에서 전사 예산을 넘지 않고, 절대 타임코드와 중복 제거가 정확하며, full 모드 fallback이 유지됨.

### RC4. yt-dlp 업데이트와 롤백

1. 현재 고정 버전을 control로 보존한다.
2. 후보 버전의 공식 자산·라이선스·SHA-256을 별도 staging에서 검증한다.
3. 같은 공개 영상으로 메타데이터·다운로드·취소·재개를 A/B 비교한다.
4. 실패하면 control 버전으로 즉시 복원하고 캐시를 섞지 않는다.

앱 자체 온라인 자동 업데이트는 이번 버전에 넣지 않는다. 검증된 새 버전을 다음 앱 빌드에 고정한다.

### RC5. 실제 영상 회귀와 패키지

- 보존된 2분·1시간 5분 한국어 로컬 영상
- 지정 채널의 실제 1~2시간 공개 YouTube 단일 영상
- 8시간 합성 또는 실제 로컬 영상의 빠른 분석
- 취소·강제 종료·재개·자식 PID 0개
- 설치 후 ACL·해시·개인 경로 문자열·고아 작업 관리
- 실제 NSIS 설치본에서 플레이어·CSV·삭제

완료 조건을 모두 통과한 뒤에만 `0.3.2` 버전 문자열을 확정하고 설치 파일을 만든다.

### RC6. 오픈소스 공개와 GitHub Release

- private staging의 검증된 결과에서 공개 허용 파일만 깨끗한 이력으로 내보낸다.
- 승인된 `LICENSE`, `CONTRIBUTING.md`, `SECURITY.md`, 제3자 고지를 포함한다.
- 공개 export를 다시 secret·개인정보·대용량 바이너리 검사한다.
- `hangokudao/vod-scout` public 저장소에 소스를 공개하고 이 저장소를 이후 정본으로 삼는다.
- `VOD-Scout-0.3.2-windows-x64-setup.exe`, `SHA256SUMS.txt`, `SBOM.spdx.json`을 GitHub Release 자산으로 제공한다.
- 공개 URL에서 설치 파일을 다시 내려받아 SHA-256, 표시 버전, 설치·실행을 검증한다.

완료 조건: public 소스와 설치 EXE가 모두 접근 가능하고, 공개용 이력 검사와 직접 다운로드 스모크가 PASS. 라이선스가 결정되지 않았거나 설치 자산이 빠지면 `HOLD`다.

## 자원 기준

- `active-chunk.wav`는 최대 한 개만 존재한다.
- 채팅 raw frame 전체를 한 번에 메모리에 읽지 않고 스트리밍 처리한다.
- validation은 30초 간격 CPU·working set·private bytes·디스크 크기·자식 PID를 기록한다.
- 취소 후 10초 안에 FFmpeg·Whisper·yt-dlp 자식 PID가 0개가 된다.
- 빠른 분석은 계산된 전사 예산을 넘지 않는다.
- 임계값은 실제 기준선 측정 후 릴리스 문서에 숫자로 고정한다. 측정 전 임의 숫자를 PASS 기준으로 만들지 않는다.

## 중단 조건

- GitHub 대상 계정이나 private 상태를 확인할 수 없음
- secret scan에서 실제 키 발견
- 설치 경로가 일반 사용자에게 쓰기 가능
- 설치본·도구·모델 해시 불일치
- HIGH 보안 항목 미해결
- 체크포인트가 다른 분석 옵션 결과를 재사용
- 실제 작업 데이터 삭제 가능성이 있는 테스트
- 공개 라이선스 미결정 또는 public Release 설치 자산 누락

중단 시 마지막 PASS 기준선으로 돌아가며, 실패를 숨기고 다음 RC를 쌓지 않는다.
