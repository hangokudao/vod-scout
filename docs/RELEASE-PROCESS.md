# 버전업·릴리스 절차

## 완료 조건

버전업은 단순히 버전 문자열이나 설치 파일을 바꾸는 작업이 아니다. 아래 항목이 모두 실제 결과와 일치해야 `PASS`다.

1. 범위와 비범위를 먼저 고정한다.
2. 세 버전 정본과 설치 파일명을 일치시킨다.
3. 관련 단위 테스트와 실제 진입점 E2E를 통과시킨다.
4. PR 또는 PR 형식 자체 리뷰를 마친다.
5. 버그·보안 수정과 알려진 문제를 변경 이력에 기록한다.
6. 설치 파일과 핵심 리소스의 크기·SHA-256을 기록한다.
7. 이전 PASS 설치본과 롤백 절차를 남긴다.
8. 공개 릴리스라면 승인된 라이선스·커뮤니티 문서·체크섬·SBOM과 GitHub Release 직접 다운로드 검증을 마친다.

## 필수 산출물

| 산출물 | 역할 |
|---|---|
| `docs/V{버전}-RELEASE.md` | 버전별 설계·구현·검증·리뷰 정본 |
| `CHANGELOG.md` | 사용자 관점 업데이트·버그·보안 이력 |
| `docs/DEBUGGING.md` | 재현 가능한 디버깅 근거와 회귀 테스트 |
| `BUILD-MANIFEST.md` | 설치본·바이너리·모델·도구 해시 |
| `HANDOFF.md` | 현재 상태와 다음 세션 복구 지점 |
| `SHA256SUMS.txt` | 공개 Release 자산의 체크섬 |
| `SBOM.spdx.json` | 공개 설치본의 소프트웨어 구성 명세 |

## 버전별 릴리스 문서 형식

```markdown
# VOD Scout vX.Y.Z 릴리스 기록

상태: PASS | HOLD | BLOCKED

## 목표와 비범위
## 사용자 변경 사항
## 내부 변경 사항과 체크포인트 호환성
## 버그 수정
## 보안 수정
## 테스트 환경과 결과
## PR 형식 자체 리뷰
### 변경 파일
### 위험과 회귀 가능성
### 발견 사항과 조치
## 설치본과 SHA-256
## 알려진 문제
## 롤백 방법
```

## PR 형식 자체 리뷰 체크리스트

- 사용자 입력과 URL 검증이 우회되지 않는가?
- 파일 읽기·쓰기·삭제 경로가 작업 폴더 밖으로 확장되지 않는가?
- 이전 버전 체크포인트가 잘못 재사용되지 않는가?
- 취소·앱 종료 시 FFmpeg·Whisper·yt-dlp 자식 프로세스가 남지 않는가?
- 내장 바이너리·모델의 버전과 SHA-256이 명세와 일치하는가?
- API 키나 영상·전사 데이터가 외부로 전송되지 않는가?
- 1~8시간 입력에서 메모리·디스크 사용량이 계속 증가하지 않는가?
- 실패한 테스트와 미확인 환경을 `HOLD`로 남겼는가?

## 공개 오픈소스 릴리스 추가 게이트

- 루트 `LICENSE`, `CONTRIBUTING.md`, `SECURITY.md`가 실제 공개 정책과 일치하는가?
- 공개용 Git 이력에 secret·개인정보·영상·전사·로그·절대 사용자 경로가 없는가?
- 설치 EXE는 일반 Git 커밋이 아니라 GitHub Release 자산으로 제공되는가?
- Release에 설치 EXE, `SHA256SUMS.txt`, `SBOM.spdx.json`, 릴리스 노트가 모두 있는가?
- GitHub Release에서 새로 내려받은 설치 파일의 SHA-256·버전·실행이 확인됐는가?
- public 저장소의 Actions 권한·fork secret·보안 신고 설정을 검토했는가?

## 릴리스 게이트

- `PASS`: 요구사항, 테스트, 리뷰, 문서, 패키지 해시가 모두 확인됨
- `HOLD`: 구현은 존재하지만 실제 미디어·설치본·보안 근거 일부가 미확인
- `BLOCKED`: 외부 권한, 입력, 도구 또는 해결되지 않은 실패로 진행 불가

`HOLD`나 `BLOCKED`를 숨기기 위해 문구를 완화하거나 테스트를 삭제하지 않는다.
