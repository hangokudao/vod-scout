# VOD Scout 제품·개발 계획

상태: **v0.3.2 공개 완료 · v0.3.3·v0.4.0 요구사항 고정**
대상: Windows 10/11, 긴 방송을 혼자 정리하는 버튜버·클리퍼

## 작업 분담

- 프론트엔드 디자인과 전반적인 UI/UX 설계·구현: Orca-Claude

## 버전 작업 실행 및 통합 규칙

### 공통 실행 방식

- 사용자가 특정 버전의 작업 시작을 명시적으로 승인한 경우에만 해당 버전을 시작한다.
- 오케스트레이터는 해당 버전 계획서의 범위·담당·완료 조건 안에서 작업 배정과 상태 관리만 한다.
- 계획서에 없는 기능 추가, 리팩터링, 의존성 추가, 폴더 개편은 구현하지 않고 후속 목록에 기록한다.
- 담당 범위나 공통 규격이 충돌하거나 완료 조건이 불명확하면 추측하지 않고 중단·보고한다.
- 동시에 코드를 수정하는 작업은 기본적으로 백엔드와 프론트엔드 두 갈래까지 진행한다. 읽기 전용 검토는 이 수에 포함하지 않으며, 추가 병렬 작업은 충돌이 없을 때만 Sol이 조정한다.
- 구현 작업은 Orca goal에서 수행하며, Orca가 관리하는 워크트리·터미널·저장소 상태는 `orca-cli`를 통해 관리한다.
- 현재 Codex 대화는 `orca-cli`를 통한 goal 전달과 상태 확인만 담당하며, 저장소 파일·워크트리·터미널을 직접 수정하지 않는다.
- 실제 구현·통합·테스트·PR은 Orca 내부 조정자(Sol)와 작업자들이 담당한다.

### 워크트리·브랜치·PR 처리

- 각 작업자는 자신의 워크트리와 작업 브랜치에서 구현하고 필요한 커밋을 남길 수 있다.
- Sol은 작업 브랜치를 통합 브랜치에 합친 뒤 통합 테스트를 수행한다.
- 통합 테스트가 끝나면 통합 브랜치를 push하고 PR을 생성한다. `main`에 직접 push하지 않는다.
- PR 병합과 배포는 사용자의 별도 승인을 받은 뒤 진행한다.

### v0.3.3·v0.4.0 완료 순서

1. v0.3.3을 구현·검증·커밋·통합·PR까지 진행하고, PR 병합 승인을 기다린다.
2. v0.3.3 병합과 인계를 확인한 뒤 v0.4.0을 별도로 시작 승인한다.
3. v0.4.0도 같은 절차로 구현·검증·커밋·통합·PR까지 진행하고, PR 병합 승인을 기다린다.

한 버전의 시작 승인은 다음 버전의 시작 승인을 포함하지 않는다.

## 제품 정의

VOD Scout는 완성 쇼츠를 자동 제작하는 프로그램이 아니라, 긴 VOD에서 먼저 확인할 후보와 그 근거·전후 맥락을 보여 주는 오프라인 편집 보조 프로그램이다. 최종 채택과 실제 편집은 사람이 결정한다.

공개 제품은 다음 조건을 유지한다.

- 비개발자가 설치할 수 있는 Windows 설치 파일 제공
- 영상·오디오·전사를 외부 서버로 보내지 않는 기본 경로
- API 키와 구독료 없이 핵심 분석 가능
- 후보 선정 근거와 원본 타임코드 확인 가능
- 취소·재개·작업 삭제·체크포인트 복원 가능
- 오픈소스와 공개 검토 기록 제공

## 제품 우선순위

1. **최적화와 안정성**: 8시간 입력에서도 메모리·디스크가 무제한 증가하지 않아야 한다.
2. **검토 속도**: 후보를 정렬하고 전후 맥락과 함께 빠르게 확인해야 한다.
3. **후보 품질**: 순간 반응뿐 아니라 이어지는 하나의 사건과 이야기 흐름을 찾아야 한다.
4. **선택 가능한 정밀도**: GPU와 더 큰 모델이 없어도 완료되고, 있으면 선택적으로 빨라져야 한다.
5. **설명 가능성**: 자동 판단 결과에 시작·절정·마무리 근거를 남겨야 한다.

## 현재 구현 범위

- 로컬 영상과 공개 YouTube 단일 영상 입력
- yt-dlp·Deno·FFmpeg·ffprobe·whisper.cpp CPU 실행 경로
- 한국어 Whisper `base`, 무음·영어 반복 환각 억제
- 빠른 분석·구간 지정·전체 정밀 분석
- 오디오 반응·발화 밀도·채팅 움직임 기반 후보
- 후보 중복 제거, 앱 안의 해당 시점 재생, 채택·보류·제외
- 경과 시간·예상 남은 시간, 취소·재개·앱 재실행 복원
- 작업 용량·삭제, 타임코드 복사, CSV 내보내기
- GitHub Releases 기반 업데이트 확인·설치

현재 GPU 음성 인식, 채팅 글자 인식, 채팅 영역 자동 탐색, 이야기 구간 탐색, 사용자 API를 이용한 LLM 재정렬은 지원하지 않는다.

## 최적화 원칙

- 전체 영상은 음량·발화·장면·채팅 움직임 같은 저비용 신호로 먼저 훑는다.
- 정밀 전사와 글자 인식은 상위 후보와 주변 맥락에만 적용한다.
- 전체 프레임, 전체 PCM, 전체 전사를 한꺼번에 메모리에 올리지 않는다.
- 처리 결과는 단계별 체크포인트와 입력·설정 지문으로 재사용한다.
- CPU 경로를 기준선으로 유지하고 GPU 실패 시 같은 청크를 CPU로 다시 처리한다.
- 설치 파일에 LLM 실행기나 대형 AI 모델을 포함하지 않는다.
- 성능 개선은 같은 입력의 처리 시간·메모리·디스크·품질을 변경 전후로 비교해 증명한다.

## 이야기 구간 요구사항

2시간 영상 안에 약 10분 동안 하나의 사건이 시작되고 전개된 뒤 절정과 마무리로 이어진다면, 정확한 편집점이 아니더라도 사용자가 검토할 만한 시작점과 끝점을 제안해야 한다.

이를 위해 다음 두 결과를 구분한다.

- **이야기 후보**: 수분 단위로 이어지는 하나의 사건
- **반응 후보**: 이야기 안에서 쇼츠로 다시 자를 수 있는 15~90초 핵심 순간

규칙 기반 연결이 기본이며 외부 AI는 사용자가 API를 등록하고 명시적으로 실행할 때만 상위 후보를 보조 평가한다.

## 8시간 입력 지원 조건

“8시간 영상 지원”은 실제 8시간 입력에서 다음 결과를 확인한 뒤에만 표시한다.

1. 처음부터 끝까지 완료
2. 처리 시간, 피크 메모리, GPU 메모리, 임시 파일 최대 크기, 최종 작업 용량 기록
3. 취소 후 마지막 완료 단계부터 재개
4. 앱 종료·재실행 후 재개
5. 남은 FFmpeg·Whisper·GPU 자식 프로세스 0개
6. 전체 PCM·원본 프레임 누적 없음
7. 후보 타임코드와 근거가 원본과 일치
8. 사람이 표시한 이야기 구간과 제안 결과의 겹침·시작 오차·끝 오차 기록

합격 수치는 v0.3.2 기준선과 1~2시간 실제 영상 측정 후 고정한다. 측정 전에는 임의 숫자를 PASS 기준으로 사용하지 않는다.

## 추가로 필요한 제품 기능

- 분석 시작 전 예상 시간·저장 공간 안내
- CPU/GPU와 모델 상태를 확인하는 하드웨어 진단
- `빠르게`, `균형`, `정확하게` 성능 단계
- 필요할 때 받은 모델의 출처·크기·해시·삭제 관리
- 후보별 분석 방식·모델·장치·근거 정보
- 이야기 후보를 사람이 수정하고 평가할 수 있는 화면
- 성능 진단 보고서와 품질 평가 자료 내보내기
- 다양한 방송 화면을 비교하는 기준 영상 목록
